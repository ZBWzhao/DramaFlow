# 30 · 全片输出结构 / 结构校验 / 有限修正

> 本册管「交付什么、怎么自查」。**提示词正文不由你写**：每条分镜只交结构化字段，服务端渲染正文（见 A10.2）；写法见 `drama_craft`。

## A10. 输出结构

### A10.1 全片总览（中文，给人看）

```text
全片总览
· 目标模型：Seedance 2.X
· 用户目标总时长：（严格 / 参考 / 未指定）
· 单镜口径：一镜一段，3–8s（常规 4–6s）
· 理论最少镜数：⌈总时长 / 8⌉（仅下限）
· 全片实际镜数：X 镜
· 全片镜表：G01 … GXX（每镜 duration_s + 全局时间范围 + 核心节拍 E##）
· 批次方案：Batch 1 = G01–G06；Batch 2 = ……
· 当前输出批次 / 下一批待交付镜
· 资产总表（角色/场景/道具：node id + name + 一致性标签）
· 场景/时间变化表
· 各连续场景世界轴线
· 情绪曲线（按原剧情时间顺序）
· 关键节拍标签
· 风格 + 运镜节奏
· 时长约束冲突（无则写「无」）
· 源剧情保真状态：通过 / 标注问题
```

**长集规则：** 即使当前只交付 Batch 1，也要先规划后续全局镜号，避免每批重新切分导致漂移。

### A10.2 每镜字段（交服务端渲染）

| 字段 | 要求 |
|---|---|
| `no` | 镜号，与总览 G## 对应 |
| `duration_s` | 3–8 的整数，一镜一段 |
| `shot_size` | 枚举值（全景/中景/近景/特写/大特写…按系统枚举） |
| `camera` | `height` 机位高度 / `angle` 角度 / `movement` 运动，三字段必填 |
| `subjects[]` | `id`（资产 node id）/ `screen_pos` / `gaze`（≥2 主体必填）/ `start_state` / `end_state` |
| `props[]` | `id` / `state` |
| `action` | 本镜动作，用 `@名字` 引用资产 |
| `focus` | 焦点落点 |
| `light` | `direction` / `color` / `contrast` |
| `sound` | 同期声与环境音 |
| `dialogue` | `text` 原文 / `duration_s` |
| `forbidden` | 本镜真实禁止项，3–5 条 |

- **禁止在节点里写长正文或成品提示词**；正文由服务端渲染写入 `data.prompt` 并置 `data.rendered_by = "server"`。人工改过的置 `"human"`，生成不覆盖。
- `action` 里 `@名字` 引用资产即锁定外观，**不重描外貌**（见 `drama_craft` §3.1）。
- `start_state` / `end_state` 写绝对状态，不写「延续上一镜」。
- 一镜一个连续镜头，不写段内时间分段（见 `20-beats-budget.md` §A3.3）。

### A10.3 资产节点字段

`kind`（character/scene/prop/style）、`name`、`anchors`、`forbidden`、`consistency_tags`、`spec`。`spec` 写单角度单图（见 `drama_craft` §1.2），**不得出现「三视图」**。

## A11. 结构校验 + 有限修正

A11 只管「能不能生成、剧情有没有被挤坏」；表现层抛光在 `50-polish.md`。

### A11.1 校验清单

**结构：** `shots` 非空；`duration_s ∈ [3,8]`；`shot_size` 在枚举内；`camera` 三字段齐；`subjects` 非空；≥2 主体时每人 `gaze` + `screen_pos` 必填；`action` 里的 `@名字` 全部能在 `subjects/props` 找到（引用闭包）；`forbidden` 非空；资产节点 `kind/name/anchors/consistency_tags/spec` 非空且 `spec` 无「三视图」。

**预算：** 全片镜时长合计符合严格总时长，否则显式标冲突；单镜 ≤ 6s 为默认纪律；所有对白在所属镜时间窗内可自然说完；串行动作、反应、必要停顿有真实时间，不靠瞬移或异常语速；长剧情先有完整全片镜表再按批交付。

**保真：** 有 `E##` 账本且每个会改变剧情状态的句子可映射；无新增/删除/替换/改归属/改顺序；没有把「父母/家长」擅自具体化；没有为连续性补前史、补道具来源或补桥接动作；情绪曲线未被用于重排剧情。

**连续性：** 已对每对相邻镜判定「连续关联 / 局部状态关联 / 无连续关联」；连续关联镜的世界位置、相对关系、姿态、朝向、手部占用无矛盾；关键道具完成持有人/位置/数量/状态/可见性链条；场景持续状态合理继承；相邻镜衔接满足镜头差异规则（见 `40-staging-continuity.md` §A7.3）。

**稳定性：** 高风险镜已按 A11.4 降复杂度。

### A11.2 有限修正（防死循环）

1. 一次性汇总所有失败项；
2. **只做一轮集中结构修正**：只许改镜边界、镜头承载、时长预算、摄影表达、锁定信息，**不得改任何 `E##` 的事件内容、执行者、对象、数量、顺序或台词**；
3. 修正后只复核受影响项及其直接连续性；
4. 再进 A11.3/A11.4，全部通过后进抛光。

**禁止 A11 ↔ 抛光来回递归。** 一轮后仍有「用户要求彼此不可同时满足」的硬冲突（如严格 30s 但原文对白自然朗读已超 30s），保留用户原文并在总览标「时长约束冲突」，不继续重算。

### A11.3 剧情保真审计（进抛光前必做）

单向比对，不向用户展示内部账本：

1. 按顺序读 `E01 → E02 → …`，确认每个都在最终某镜出现，执行者/对象/台词/顺序未变；
2. 反向扫描所有会改变世界状态的动作，找不到源 `E##` 就删除该 AI 新增动作；
3. 摄影、构图、景别、对焦、已有动作的物理结果与拟音可无 `E##`，但不得产生新的剧情事实；
4. 删掉 AI 新增动作后出现「状态从哪来」→ 把用户给出的状态直接当该镜初态，不补前史；
5. 源文本自身有缺口/矛盾 → 保留并标注，不自行编桥。

**目标不是让剧情更顺，而是确认交付物与用户剧情是同一件事。**

### A11.4 生成稳定性预检（降风险 · 不承诺不崩）

**高风险触发项**（任一即标记并主动降复杂度）：3 个及以上主体同时大幅移动/互相遮挡/接触；双手或多人同时操作小道具（交接、系扣、倒液体、擦拭）还叠加复杂运镜；大幅身体动作与近景手部细节同时；镜子/玻璃/强反射/透明容器/多影；包装小字、手指、液体、机械结构既要近距离准确又要高速运动；同镜极浅景深 + 强遮挡 + 快运镜 + 多角色表演；引用参考图过多且互相冲突；提示词自相矛盾（人物完全固定又要快速换位）。

**降风险顺序**（按序做，直到不再过载）：
1. **删无关控制，不删剧情**：删掉不影响本镜的镜头术语、泛化负面词、无关材质细节。
2. **摄影机先简化**：精细手部/道具接触时固定或单一平稳运动，不同时叠加推拉、环绕、快摇、移焦。
3. **让关键接触完整可见**：交接/拿取/擦拭/开合选能同时看见手和道具的景别，不在接触点被画框、身体、前景遮住。
4. **降低景深冲突**：关键手部与道具都要可辨时不用极浅景深虚化其一。
5. **复杂动作与复杂摄影不抢同一时刻**：源剧情允许就在已有 `E##` 边界拆镜；要求同时发生就保持同时，降低摄影机与背景复杂度。
6. **参考图只留本镜真需要的**，多张用途不同要划清范围，冲突按 `drama_craft` §1.2 处理。
7. **定向 Avoid，不全片堆负面词**：按本镜真实风险加额外手臂/手指、肢体融合、身份漂移、道具复制消失、物件穿手/穿桌、穿模、几何融化、镜像多出人物；无此风险不加。
8. **仍然过载才重分镜**，只能用已有 `E##` 边界，不删、不增、不改顺序、不改同时关系。

**通过标准：** 每镜一个清楚的主要观看任务；人物数量、肢体接触、道具数量和动作因果在当前景别可看清；没有互相矛盾的摄影机命令；没有诱发重复主体的无必要镜像反射；参考绑定不争同一维度；身份/服装/商品结构/关键道具已在适当字段锁定；高风险镜的 `Avoid` 只针对真实风险。
