# 10 · 从哪里开始 / 画布推进 / 确认与恢复

> 本册是 workflow 的入口与执行层。**提示词写法只看 `drama_craft`**，本册不重复任何模板。

## 1. 宿主工具映射（最高优先级）

正文里的原版工具名是概念说明；实际调用必须用本轮 `<tools>` 中存在的 Python 工具，绝不能编造。

| 原版概念 | Python 宿主实际工具 |
|---|---|
| 剧本归属识别（新制作请求的第一个画布工具） | `identify_story` |
| `skillOperator` | `read_skill(name, path)` |
| 读画布 / 节点 / 边 | `get_canvas`，必要时 `read_file` 读 `content_path` |
| 建节点 | `add_node` / `add_nodes` |
| 写正文、写提示词 | `set_text` |
| 连边 | `connect_nodes` |
| 节点配置 / 资产字段 / 状态 | `update_node` |
| 结构化分镜写入 | `set_storyboard` |
| 生成节点 | `add_node`/`add_nodes` 建 `image_gen`/`video_gen`，再连提示词 |
| 用户上传的图片 / 视频 | 前端创建独立 `image`/`video` 节点；图片输出 `IMAGE`，视频输出 `VIDEO` |
| 模型能力与媒体生成 | `list_media_models` / `generate_media` / `run_canvas` |
| `askUser` | 无提问工具时，在回复中只问必要问题并等待 |

- 画布正文存 `assets/<node_id>/content.md`；`set_text` 成功后不必再直接改文件。
- prompt 节点必须在 `data` 写 `segment_no`；把 prompt 的 `prompt` 输出连到生成节点的 `prompt` 输入。
- 文字生产包完成后必须再次 `get_canvas`，修复体检问题。
- 用户上传的 `image`/`video` 是真实素材，可连 `ref(IMAGE)` / `video_ref(VIDEO)`，不得当成 AI 产物或擅自替换。
- 每张画布只承载一个独立剧本：每次新创意先 `identify_story`；核心人物与事件不同就建新画布，只有明确续写才复用。后续节点用返回的画布名，禁止惯性追加。
- Mock Provider 只验证链路：可建完整生成节点与方案，但无明确授权不执行 `run_canvas`，不能把占位首帧说成真实视频。

## 2. 从哪里开始

先判断本次交付、已有资料和用户明确限制，沿用已知的时长、风格、画幅、语言、版本；只问影响结果且无法合理判断的缺项。

| 已有输入 | 处理方式 |
|---|---|
| 创意或一句话 | 补齐人物目标、阻力、结果，形成可审阅故事与完整剧本 |
| 小说 / 原著片段 | 确认改编范围，保留原文，追踪事件、人物、对白与未知信息，转成可视听剧本 |
| 已定稿剧本 + 目标是制作/生成/继续/修订视频 | **无论用户是否提「Seedance」「提示词」都立即进入 Seedance 执行态**（§3）；未指定模型时只用一次简短提问确认 2.0 还是 2.5 |
| 已定稿剧本 + 只要资产、剧本阅读、诊断或非视频 | 只做明确要求的非视频范围，不因有定稿剧本就自动生成视频提示词 |
| 续集或已有制作 | 读指定的历史、当前节点与采用记录，确认范围后从实际进度继续 |
| 指定片段、资产或修改 | 只处理该范围与确实受影响的依赖，不重跑整条链 |

## 3. Seedance 路由锁存（最高优先级入口规则）

同时满足两项即**自动视为 Seedance 任务**，不要求用户说出「Seedance」「2.0/2.5」：
① 已有可执行的定稿剧本/时间轴/镜头剧情段/已确认片段，或用户要求继续已有视频制作；
② 当前意图是制作、生成、继续、修订视频，或对即将生成的视频做配置。

命中即锁存为 **Seedance 执行态**：

- **先进入剧本与工艺规划，再处理画布执行配置**：目标模型属于必要输入，不算画布配置；不得先调 `get_canvas`、先问 provider/resolution/ratio/mode，或先做通用分镜。
- 用户没指定 2.0/2.5 时**锁存后用一次简短提问确认**，回答后立即从 A0 继续；已指定则直接采用，不再重复问。
- 模型确认与执行配置询问**分开**：画幅/分辨率/原生音频/参考模式/供应商只是同一任务的执行参数补充；用户回「16:9」「1080p」「2.5」等短答案视为配置补充，不是新任务，不得解除锁存。
- 只有用户明确改成「不要生成/修订视频提示词，只做资产、剧本、咨询」才解除锁存。
- 执行阶段若实时节点不支持已选模型，只报告真实能力冲突并回到受影响项；**不得用配置层默认模型静默替换路由**。

**阶段硬隔离（强制）**：从进入执行态到最终提示词定稿，只读本册 + `drama_craft` + `20/30/40/50` 四册；不得读 `references/sourceAndScript.md`、`references/methods/*` 或任何旧分镜规则来补第二套分段/时长/站位/表演/运镜/连续性/声音/模板/QA。

- **唯一例外**：需要「无参考图时补参考资产/设计提案」时，才按需读 `references/assets.md`、`methods/visualDesign.md`、`methods/colorAndLight.md`，只取外观/空间/材质/光线，不得把时长、镜头、表演或叙事方法带回提示词规则。
- 提示词定稿后，如用户明确要求连参考、写生成节点或生成/验收媒体，才退出隔离进入执行层（`references/canvasExecution.md`、`references/stateAndDelivery.md`）；执行层只能搬运已定稿 prompt、连真实参考、设真实参数、核验结果，不得改写已定稿内容。

## 4. 画布推进

工作区用宿主当前项目；未打开画布时说明具体条件，继续可完成的文字部分。只创建当前阶段需要的节点。

| 阶段 | 当前成果 | 需要读取 |
|---|---|---|
| 1. 内容与范围 | 原文或剧本文本节点、必要制作简报 | `references/sourceAndScript.md` |
| 2. 资产 | 本次范围的角色/场景/道具清单及实际采用图片 | `references/assets.md` |
| 3. 编织提示词（剧本→分镜→资产→首帧→视频段→校验） | 全片规划、分段与正式提示词 | 写法见 `drama_craft`；流程 `20-beats-budget.md` → `40-staging-continuity.md` → `50-polish.md` → `30-output-check.md` |
| 4. 生成与采用 | 片段生成节点、真实输出、反馈与采用记录 | `references/canvasExecution.md`、`stateAndDelivery.md` |
| 5. 交付或继续 | 有效剧本、素材与片段索引、实际完成范围与下一步 | `references/stateAndDelivery.md` |

一个剧情片段默认对应一份完整提示词、一个视频生成节点；不默认给每个镜头先生成关键帧。连线传递实际素材，不代表审批或自动调度。

## 5. 创作方法（仅 Seedance 之前 / 成品之后）

这些方法只用于提示词阶段之前的创作改编与资产设计，或成品之后的媒体执行；进入提示词阶段后不读，也不得覆盖工艺规范。

| 问题 | 读 | 落实为 |
|---|---|---|
| 创意、人物驱动、因果、大纲、续作 | `methods/storyDevelopment.md` | 行动命题、事件链、选择与结果 |
| 小说视听化、场景、心理、对白与时长 | `methods/screenAdaptation.md` | 场次、完整行动与声音、改编提案与估时 |
| 外观、空间、道具结构及持续状态 | `methods/visualDesign.md` | 资产锚点、空间母版与变体 |
| 风格、材质本色、受光与调色 | `methods/colorAndLight.md` | 共享视觉依据、场景光线、片段约束 |
| 真实媒体执行与验收 | `canvasExecution.md`、`stateAndDelivery.md` | 只执行已定稿 prompt、连真实参考、核验真实结果 |

- `subAgent` 只可用于提示词阶段之前的长篇事实提取与资料整理；**提示词阶段禁止让 subAgent 独立起草、重写或优化分段 prompt**。
- 少量文字、资产盘点、连线和布局直接做，不安排固定岗位或额外审查轮次。

## 6. 确认与执行

- 展示实质阶段成果并确认是否调整；已明确批准的内容与连续制作范围直接沿用，不把每个工具调用或无需求的子步骤变成提问。
- 内容确认、算力授权、结果采用**分别记录**。生成前展示可审阅方案：对象与数量、模型、完整提示词、实际参考、规格、执行次数；对用户统一称「消耗算力」，无法查询时写「算力消耗未知」。
- 用 `askUser` 或明确回复取得授权；已批准的同一方案/批次不逐节点重复问，新增数量、改变方案或额外重试时核对授权是否覆盖。「继续」、沉默、表单失败都不构成新生成授权。
- 有对白不等于必须有外部音色样本；提示词内声音写法只服从 `drama_craft`，执行时只通过 `canvasExecution.md` 核对模型是否支持原生声音。

## 7. 完成与恢复底线

- 正文通过节点函数保存，路径从实际 `data.textPath` 读；跨轮制作用一个简洁状态记录 + 一个总览节点，沿用现有台账，不因缺模板要求重做。
- 待确认或已采用的文本要有固定版本依据；生成保留本次提示词、参数、参考与旧输出。确认后再核对实际节点，防止用户等待期间的修改被当作已批准；已采用素材固定在素材节点，修订另建候选。详见 `stateAndDelivery.md`。
- 原生媒体节点返回 `generating` 只表示开始，不能宣称完成。无真实状态/等待工具时，完成本轮已授权且无依赖的工作后登记并告知用户完成后回复，再回读节点；不编造自动唤醒或后台轮询。连续片段的后段生成需等前段采用并取得真实交界状态。
- 视频路径不代表 Agent 看过视频；只按实际媒体读取能力核验，能力不足时由用户预览并报告问题、交界状态与采用决定，并明确 Agent 未核验的部分。交付区分已生成片段、用户采用片段、已合成成片、已归集副本。
