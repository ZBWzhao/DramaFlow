# LibTV 画布亮点分析（实测版）

> 观察对象：LibTV 公开作品《长生无忌第20集》的**真实生产画布**（数百节点、真实商用项目，非 demo）。
> 观察方式：作品详情页 https://www.liblib.tv/detail/8275c1e729f348b28d5ba94615aaf370 → 点「查看制作过程」→ 匿名进入**只读画布**（顶部标「只读模式，如需创建请点击｜复制项目」）。用 headless Chromium 实测缩放、DOM、节点结构并截图。
> 结论：这个画布"好"不在花哨，而在**它把"几百个镜头素材"这种真实体量的生产现场做成了能看懂、能导航、能播的东西**。下面每条都给了证据与可借用点。

---

## 一、先说结论：它赢在哪 6 件事

| # | 亮点 | 一句话本质 |
|---|---|---|
| 1 | 语义缩放（LOD 三档） | 10% 看整条流水线、53% 看镜头清单、70%+ 直接在节点里看片 |
| 2 | 视口虚拟化 | 只挂可见节点：DOM 里 `react-flow__node` 只 3–5 个，`<img>` 从 182 掉到 36 |
| 3 | 画布即播放器 | 视频节点不是缩略图，是**带时间轴的内联播放器**（0:00 / 0:15） |
| 4 | 只读分享 + 一键复制项目 | 把"制作过程"变成公开增长入口，看完就能拿走复刻 |
| 5 | 降噪工具组 | 隐藏节点连线 / 小地图 / 缩放档位 / 适应画布，"节点洪流"可控 |
| 6 | 恢复性 UI | 平移进空白区弹「当前视窗没有节点 / 返回节点」，永不迷路 |

---

## 二、逐条证据

### 1. 语义缩放：同一个画布，三档信息密度

实测 Ctrl+滚轮：10% → 53% → 70% → 160%，每一档渲染的**内容本身**在变，而不是简单缩放：

- **10%（默认 fit，一屏全览）**：节点只剩纯缩略图，**没有标题、没有边框、没有端口**。数百个镜头/定妆图铺满屏幕，像一张"生产现场卫星图"——用户 3 秒就能知道这个项目有多少镜头、分几条线。
- **53%（中景）**：每个节点浮出头部条：`▶ 播放图标 + 节点名（如「森林大战镜头1 - 副本」「截图 00:07.743」）+ 右上角分辨率「1280 × 720」`，媒体区左上角一枚 `AI生成 / 人物视频` 胶囊徽标。
- **70%（工作档）**：媒体区变成可播的视频，出现时间轴 `⏸ 0:00 ── 0:15`；hover 出现浮动工具条（DOM 类 `node-floating-ui`）。
- **160%（审片档）**：单个镜头占满屏，只剩大图和 `AI生成` 标签，其它 chrome 全部让位。

> 对照证据：`d-zoomin1.png`（53%）、`02-node-70pct.png`（70%）。

**为什么这招厉害**：它把"缩放"从"放大镜"变成了"换视图"。同类工具在小比例下往往是**缩小版的完整卡片**（标题、按钮、端口全都在，糊成一团），而它选择了"低倍率下只留像素价值最高的东西——画面"。

### 2. 视口虚拟化：几百节点不卡

- 页面里 `.react-flow__node` 实际只挂了 **3–5 个**；`document.images` 在 10% 时 182 张、53% 时 36 张、70% 时 34 张。
- 节点坐标系跨度极大（实测首个节点 `x=-53551, y=-5244`，节点真实宽 1600px），说明画布世界坐标是"无限画布"，靠视口裁剪 + 只渲染可见区域扛住体量。
- 渲染层是 **DOM 而非 WebGL**（`document.querySelector("canvas")` = 0），即用 React Flow（`react-flow__node / react-flow__handle / nodrag / nopan`）+ 自定义节点壳（`node-shell`）+ 可见性剔除。

**对我们的意义**：我们 `web/canvas.js` 的 `render()` 是 `nodes.innerHTML=""` 然后**全量 append**，每个节点还带 `<img>`；节点一多必然卡。哪怕不做完整虚拟化，只要加 `content-visibility:auto` 或按视口过滤，也能立刻改善。

### 3. 画布即播放器

节点里直接内联 `<video>`，有播放/暂停、进度条、时长；加载失败时节点内显示「加载失败，点击重试」的重试态（截图里左侧节点就是这个状态）。

这条的价值常被低估：**做视频的人，审片的动作是"连续看"，不是"点开弹窗看"**。把播放器塞进节点，等于把"挑素材"这件事从"打开-判断-关闭"变成"一眼扫过"。

### 4. 只读分享 + 复制项目（增长回路）

作品详情页 →「查看制作过程」→ 匿名可进入的**只读画布**（顶栏明示"只读模式，如需创建请点击［复制项目］"）→ 想看细节就复制成自己的项目（要求登录）。

一次性解决了三件事：作品展示（观众看到的是"做法"而不是"成品"）、教程素材（不用录屏就能讲清一个镜头怎么来的）、拉新转化（复制项目是天然 CTA）。

### 5. 降噪工具组

左下角三个常驻控件：`切换小地图`（22,950，28×28）、`隐藏节点连线`（54,950）、缩放读数按钮 `160%`（86,950）。顶栏中央两个图标：`工作流`（776,8）、`故事板`（808,8）；右下角一个 22×22 的 `发布`。

真实项目里连线是**噪音源**：53% 时数百条长贝塞尔线交叉，几乎糊屏。它给的不是"更漂亮的线"，而是**"一键把线关掉"**——承认了复杂度，并把控制权交给用户。

### 6. 恢复性 UI（防迷路）

把画布平移到空白区域时，底部中央弹出提示条：**「当前视窗没有节点」+［返回节点］按钮 + ✕**（截图 `04-empty-viewport.png`）。

无限画布最大问题是"我飘走了"。多数产品靠小地图兜底，它多做了一步"主动发现你迷路了，并给你一个一键回家的按钮"。

## 三、也要说的弱点（别整套照搬）

1. **边线降噪是"手动"的**：默认态没有按聚焦自动降透明度，53% 以上仍然糊；只有开关，没有智能。
2. **命名靠人肉**：大量节点叫「森林大战镜头1 - 副本」「- 副本2」，说明变体管理还是靠复制粘贴，没有"候选组/版本树"这类结构。它的做法是**在空间上人工排开做 A/B 对比**（同一镜头的多个 take 并排成 2×2 网格），可读但脆弱。
3. **顶栏控件过小**：部分按钮 22×22、32×32，密集且无文字标签，可发现性靠悬停提示。
4. **故事板/工作流双视图**按钮存在，但只读模式下点击未能切换（可能需登录/作者权限），此条**未验证**。
5. **素材真实感依赖生成质量**：画面本身糊的镜头（运动模糊失败）在缩略图层看不出问题，得进 70% 才暴露——LOD 带来的"过度乐观"是副作用。

## 四、对照我们自己的画布（toonflow-py-lab）

| 能力 | LibTV | 我们现状 | 差距性质 |
|---|---|---|---|
| 渲染 | React Flow + DOM 节点 + 可见性剔除 | `web/canvas.js` 全量 DOM + SVG 贝塞尔；`web-vue` 用 Vue Flow | 架构不差，**缺剔除与降级** |
| 缩放 | Ctrl+滚轮，10%–160%+，三档 LOD | 滚轮缩放 0.25–2.5，**无 LOD**（缩到 25% 仍带标题+端口文字） | 差在"缩到多小都还是一张卡" |
| 节点内容 | 内联视频播放器 + 时间轴 | `<img>` 静态缩略图（`canvas.js:247-265`）；video 节点存首帧 | 差"审片体验" |
| 连线 | 细线无箭头，可一键隐藏 | 贝塞尔 + 箭头 + 选中高亮（`canvas.js:191-209`） | 我们箭头反而更吵，缺全局开关 |
| 迷路兜底 | 小地图 + 空视窗「返回节点」 | 有 `fit()` 适应窗口；无小地图、无空视窗提示 | 低成本可补 |
| 分享 | 只读画布 + 复制项目 | 无（需登录进入本项目） | 产品级缺口，价值最高 |
| 双视图 | 工作流 / 故事板 | `CanvasPanel.vue` 已有 `timelineClips` + `clip_order` 计算（第 161–169 行），**只差一个视图** | 半成品，容易捡 |

## 五、落地建议（按 ROI 排序，带文件定位）

### P0 — 一两天内能见效

1. **LOD 三档（改 `web/canvas.js`）**
   在 `applyTransform()` 里按 `zoom` 给 world 容器加状态类（如 `z-far` / `z-mid` / `z-near`），CSS 里控制：
   - `zoom < 0.45`：`.cnode-head{display:none}`、`.cnode-label{display:none}`、`.port-label{display:none}`，只留卡体缩略图；
   - `0.45 ≤ zoom < 0.8`：显示标题条 + 状态，隐藏端口文字只留圆点；
   - `zoom ≥ 0.8`：全量。
   （`canvas.js:129-132` 是唯一的 transform 出口，挂在这里最省事。）

2. **视口剔除 / 渲染降本**
   最省事的次序：先给 `.cnode` 加 `content-visibility:auto; contain-intrinsic-size:220px 104px`（一行 CSS，浏览器跳过屏幕外节点的排版绘制）；再考虑在 `render()` 里按 `this.s.view` 反算可见世界矩形，只 append 命中节点。

### P1 — 一两周

3. **边线降噪**：`.edge` 基础透明度降到 ~0.25，选中/上游链路高亮（已有 `hot` 逻辑，`canvas.js:202`），再加一个「隐藏连线」开关（和现有 `canvas-fit` 按钮同组）。
4. **空视窗救援**：`fit()` 已有包围盒计算（`canvas.js:499-526`），把包围盒和当前 view 比一下，若视口内无节点就显示"当前视窗没有节点 / 返回节点"，点击调 `fit()`。
5. **视频节点内联播放**：节点带 video 产物时，`<img>` 换成 `<video muted playsinline preload="metadata">`，仅当 `zoom ≥ 0.7` 才创建（否则保持缩略图），首帧用 poster。
6. **故事板视图**：`CanvasPanel.vue` 的 `timelineClips` 已经能按 `clip_order` 排出片段序列（161–169 行），把它渲染成横向 filmstrip + 拖动排序（`moveTimelineClip` 已有），和节点图用同一个 tab 切换——这是低成本高感知的一条。

### P2 — 产品级

7. **只读分享 + 复制项目**：后端加只读快照端点（`GET /api/share/<token>`，返回 `nodes/edges` 只读视图），前端复用同一个画布组件但禁用写入交互、顶栏换成"只读模式 / 复制项目"；这是把"作品"变成"获客入口"的关键一步，LibTV 整个增长回路就建在这上面。
