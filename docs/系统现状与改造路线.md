# 你的系统现在是什么样 —— 一份给产品负责人的说明书

> 这份文档写给"系统的产品负责人"：不要求你会写代码，只要求你能看懂系统怎么跑、钱花在哪、哪里会坑你、接下来怎么改。
> 想快速了解，只看 **第 0 章**；要决定下一步做什么，看 **第 3 章**；要照着验收，看 **第 5 章**。

---

## 0. 一分钟版

**这个系统本质是什么？**
一个"AI 制片厂"：你给剧本 → AI 导演（Agent）写拍摄方案（分镜、角色、场景、道具）→ 系统把方案"翻译"成 AI 模型听得懂的指令（提示词）→ 模型出图、出片 → 你挑选版本 → 系统拼成片。

**钱花在哪？** 只有 3 个地方，其它全免费：

| 花钱点 | 买的是什么 | 单价性质 |
|---|---|---|
| 资产参考图 | 角色的"身份证照片"（正面全身 + 正脸特写） | 按张 |
| 首帧 | 每个镜头的"第 0 秒画面" | 按张 |
| 视频 | 每个镜头的动态画面 | 按秒/按条，最贵 |

**现在最大的问题（一句话）：**
方案是结构化的、可靠的，但"翻译"这件事被拆散在 **6 个不同的翻译器**里各干各的，导致——
1. 你在界面上看到的提示词，**不一定是真正发出去的提示词**（有些模式下你改了它，视频完全不受影响）；
2. 每次生成**没有存完整凭证**，错了无法复现、无法追责、无法对比；
3. 生成前**看不到**要发什么、要花多少钱，只能点下去用钱试。

**已经修好的（本轮 S1–S5）**：技能文档从 97KB 单体拆成"路由表 + 5 册"、提示词从"手写长文"改成"结构化字段由服务端渲染"、校验器从"猜文本"改成"查字段"。
**还没做的**：真模型验证（S6）、生成前预览、第 3 章的三步改造。

## 1. 系统全貌

### 1.1 五个角色，各管一段

| 角色 | 是谁 | 管什么 | 一句话比喻 |
|---|---|---|---|
| 制作台界面 | `web-vue/src/studio/` 下 4 个标签页（剧本 / 资产 / 制作 / 预览） | 给你看、给你点 | 工厂的**中控屏** |
| 后端服务 | `server/studio.py` | 业务规则、拼提示词、调模型、存档 | 工厂的**车间主任** |
| AI 导演（Agent） | 大模型 + 技能文档 | 只写结构化方案，不写台词式的长提示词 | **编剧+分镜师** |
| 模型服务（Provider） | tfrouter（可切 mock 假模型） | 收指令，出图/出片 | 外包的**摄影棚** |
| 画布（Canvas） | 一个 JSON 文件 + `assets/` 目录 | 存所有节点、连线、分镜、资产、成片记录 | 唯一的**生产图纸** |

关键认知：**画布是唯一事实来源**。界面上的东西都是从画布算出来的；生成也是从画布读数据拼出来的。画布乱了，一切都乱。

### 1.2 五个阶段的流水线

| 阶段 | 你怎么触发 | 系统内部做什么 | 产物 | 花钱吗 |
|---|---|---|---|---|
| ① 新建项目 | 首页填标题/画幅/剧本 | 建画布，写入项目设定；把剧本按"第N集"切成文本节点 | 一张空画布 + 每集一段剧本 | ❌ |
| ② Agent 策划 | 剧本页点「让 Agent 开始制作」 | Agent 按技能文档写出：每镜一个分镜节点、每段一个提示词节点、每类资产节点、生成节点和连线；收尾由系统补连线、按字段渲染初始正文 | 完整的"生产包"（画布节点图） | ❌ |
| ③ 资产参考图 | 资产页逐个点生成 | 按"外观锚点+一致性标签+图种规矩+全剧风格"拼一条生图提示词，调图模型 | 每个资产每个形象一张图 | 💰 |
| ④ 首帧 | 制作页点「生成首帧」 | 用"八段式"提示词 + 各资产参考图，让模型画出这一镜的第 0 秒 | 每镜一张首帧图，锁死构图和站位 | 💰 |
| ⑤ 视频 | 制作页点「生成这一镜」或「批量生成」 | 按分镜字段拼视频提示词，带着首帧（或参考图）调视频模型 | 每个镜头 1~N 个候选版本（take） | 💰💰💰 |
| ⑥ 合成 | 预览页点「合成整集」 | 人工确认后，用 ffmpeg 把采纳的片段按顺序拼起来 | 成片 mp4 | ❌ |

### 1.3 三个钱袋子，三个"翻译器"

这是理解现有问题的关键——同一个镜头，在不同的阶段会被**翻译成完全不同的三份提示词**：

| 花钱点 | 提示词从哪来 | 带参考图吗 | 存下来了吗 |
|---|---|---|---|
| 资产参考图 | 系统按资产字段**现场拼**（`_look_prompt`） | ❌ **一张都不带** | 提示词存在资产的形象里 ✅ |
| 首帧 | 系统按镜头字段**现场拼八段式**（`_keyframe_prompt`） | ✅ 带各资产参考图 | 提示词存在首帧记录里 ✅ |
| 视频（有首帧时） | 系统按镜头字段**现场拼单镜文本**（`_shot_prompt`） | ❌ 只带首帧，不带参考图 | ❌ **没存** |
| 视频（无首帧时） | 把你在界面上看到的正文做**替换加工**（`_materialize_prompt`） | ✅ 带参考图 | ❌ **没存** |

看懂这张表，就理解了后面 80% 的问题：**四份提示词，三种拼法，有的存有的不存，且界面只展示了其中一两种。**

### 1.4 数据都住在哪

```
画布 JSON（每项目一个）
├── 节点：剧本 text / 分镜 storyboard / 提示词 prompt / 资产 asset / 生成槽 video_gen / 时间线 timeline
├── 连线：谁是谁的输入（分镜→提示词、资产→提示词的参考图）
└── 记录：每个生成槽里的 takes（候选视频）、keyframe（首帧）、tags（标签）

assets/ 目录
├── <节点id>/content.md     剧本正文
├── generated/             模型生成的图/视频
└── rendered/              合成的成片

服务内存（⚠️ 重启即消失）
└── 任务队列（produce 任务、生成任务）
```

记住最后一行：**任务状态存在内存里，服务一重启就没了**。用户已经付过钱的生成如果正好卡在重启点，就白花了。

## 2. 现在的问题

### 2.1 一句话总结

> **方向是对的（结构化方案 → 机器翻译 → 模型执行），但"翻译"和"存档"只做了一半：翻译散成 6 份各说各的，存档只存了结果没存凭证，而且用户全程看不见翻译过程。**

### 2.2 A 类：会让你白花钱或白改的问题（优先修）

| # | 问题 | 用户会感受到什么 | 危害 |
|---|---|---|---|
| A1 | **有首帧时，你改的提示词不生效** | 在制作页认真改了提示词，点生成，出来的视频跟没改一样 | 🔴 高 |
| A2 | **提示词说"按参考图"，实际一张没带** | 模型不知道角色长啥样，越演越不像 | 🔴 高 |
| A3 | **校验的不是真正要发出去的内容** | 界面显示"没问题，可以生成"，发出去的却是另一份文本 | 🔴 高 |
| A4 | **每次生成不存完整凭证** | 出一个好版本想复现，做不到；想对比两版差异，做不到 | 🔴 高 |
| A5 | **角色的两张参考图互相不参考，也不记"随机种子"** | 全身图和特写图不是同一张脸；想重新生成一样的图，做不到 | 🟠 中高 |

**A1 详解（最典型）**
制作页的提示词文本框，改的是"片段正文"。但**有首帧时**，视频真正发出的文本是系统按字段重新拼的，压根不读你改的那份。所以这个文本框在有首帧时是个"假控件"。
> 这就像你在餐厅菜单上改了菜名，后厨却按另一份单子做菜。

**A2 详解**
视频提示词里写着"身份与外观完全按参考素材（@张三、@李四）"，但那次请求的参考图列表是空的——只带了一张首帧。模型被文字引导"去找参考图"，却找不到。
> 应该写成"身份与外观完全以首帧为准"，因为这次确实只有首帧。

**A3 详解**
生成前的"体检"检查的是界面正文；而实际发出去的文本是另一个函数现拼的。两者可能不一致——体检说合格，不代表要发的文本合格。

**A4 详解**
每次生成的结果只记录了：文件路径、模型名、时长、镜号。**没记提示词、没记参考图、没记参数、没记种子。** 后果：
- 用户说"上周那个版本更好"，找不回来；
- 出片崩了，无法判断是提示词问题还是模型抽风；
- 无法做 A/B（同一段两个提示词哪个好）。

**A5 详解**
角色的"全身图"和"特写图"是两次独立生成，彼此没有参考关系，所以很可能不是同一张脸；视频只用了其中一张（被标为"当前形象"的那张）。哪张被选中，全剧就按哪张走。
> 更省钱的顺序应该是：先出全身（定脸）→ 用全身当参考出特写 → 人脸确认后才允许进视频。

### 2.3 B 类：体验问题

| # | 问题 | 用户感受 |
|---|---|---|
| B1 | **生成前是黑盒**：看不到要发什么提示词、带哪几张图、花多少钱 | 只能点下去用钱试，像开盲盒 |
| B2 | **同一个按钮两种含义**：有首帧 / 没首帧走两套完全不同的逻辑 | 同样的操作，出来的东西风格不一样，不知道为什么 |
| B3 | **批量生成没有费用预估和限额**：一次点"批量生成 20 段"就是 20 次视频调用 | 手滑一次，一天预算没了 |

补充一个 B 类小坑：**时长会被静默截断**（比如要 40 秒会被偷偷改成 30 秒），**模型会被静默替换**（项目里配的是假模型时会被换成真模型），用户都不会收到提示。

### 2.4 C 类：稳定性问题（商业化前必须解决）

| # | 问题 | 后果 |
|---|---|---|
| C1 | 任务状态存在内存，服务重启就丢 | 正在跑的视频任务消失，钱和等待时间都白费 |
| C2 | 双击"生成"= 两次扣费；失败没有自动重试和限流 | 用户多付钱、批量任务容易"几段失败几段成功" |
| C3 | 生成时读一次画布，之后画布被改，结果仍按旧数据记录 | 结果不可解释、不可复现 |

### 2.5 为什么会变成这样（不是谁笨，是演进留下的）

系统的真实演进顺序是：
1. 最早：提示词是**手写长文**，一段一大段文字，人写、模型读；
2. 中途发现手写导致"角色换脸、镜头乱切"，于是改成**结构化字段 + 服务端渲染**（这一轮 S4 做的）；
3. 但旧的"手写长文"路径还得兼容老项目，于是**两条路径并存**；
4. 每条路径各自有自己的一套"翻译函数"，越加功能越多，就有了今天的 6 个翻译器。

技能文档也是同一个故事：97KB 单个文件，什么都在里面，AI 每次全读、读不完就忘——本轮 S1–S5 已经把它拆成"一张路由表 + 5 本分册 + 一本工艺书"，这是同一个病在另一处的治疗。

## 3. 需要怎么改（三步走）

### 3.0 目标态：一次编译，到处使用

```
画布字段（唯一事实来源）
      │
      ▼  编译器（一个纯函数，唯一翻译入口）
  请求说明书 PromptSpec
  { 提示词、负面词、参考图[带角色标签]、时长、分辨率、种子、模板版本、指纹 }
      │
      ├──▶ 预览：原样展示给人看（不花钱）
      ├──▶ 生成：同一个对象交给模型（要花钱）
      └──▶ 存档：同一个对象写进 take（可复现）
```

三个"同一份"就是全部改造的目标：**预览看到的 = 生成的 = 存档的**。

### 3.1 第一步：止血（约 1–2 天，不加新功能，只修正确性）

| 项 | 改什么（人话） | 预期结果 | 怎么验收 |
|---|---|---|---|
| 1 | 有首帧时也让"你改的提示词"生效（或者明确禁用它并提示"首帧模式请改分镜字段"） | 不再出现"改了没用" | 改文本框→生成→对比发现确实按改后文本出片 |
| 2 | 视频提示词里"按参考素材"改成"按首帧"（无参考图时不说谎） | 模型不再被误导 | 生成请求里看不到"@不存在的参考图" |
| 3 | 生成前体检改为检查"真正要发出去的那份文本" | 体检结论可信 | 故意改坏一个字段，体检能报出来 |
| 4 | 每次生成保存完整凭证（提示词、参考图清单、参数） | 任何一版都能查到"当时到底发了什么" | 打开某一版的详情，能看到完整请求 |

> 这一步的价值：**先让系统不说谎**。之后的预览功能才有意义。

### 3.2 第二步：所见即所得（约 2–3 天）

| 项 | 改什么（人话） | 预期结果 | 怎么验收 |
|---|---|---|---|
| 5 | 把 6 个翻译器合成 1 个"编译器" | 提示词只有一处生成逻辑，改一次全系统生效 | 预览和生成里出现同一份提示词 |
| 6 | 制作页每段加「预览请求」：提示词全文 + 参考图缩略图 + 模型/时长/分辨率 + 预估费用 | 点生成前能完整审查 | 预览内容与生成出来的凭证完全一致 |
| 7 | 批量生成对话框升级成「本集待生成清单」：一行一段，可展开预览、可勾选、显示总费用 | 一整集批量生产前能整体把关 | 20 段一次看全，费用先算清 |
| 8 | 角色参考图改成"全身定脸 → 特写参考全身"，并记录随机种子 | 同一个角色的脸不会两张不一样，可复现 | 重出特写时脸与全身一致 |

> 这一步就是你说的"生成前让我审查提示词，不花额度"。建议落点：**制作页详情 + 批量清单用的是同一个预览组件**，不单独做页面。

### 3.3 第三步：商业化护栏（约 3–5 天，可分批）

| 项 | 改什么（人话） | 预期结果 |
|---|---|---|
| 9 | 费用预估 + 每集预算上限 + 超额二次确认 | 不会手滑烧钱 |
| 10 | 任务持久化 + 幂等（同一段短时间重复点击只算一次）+ 失败自动重试 | 重启不丢任务、不重复扣费 |
| 11 | 字段级微调界面（机位/站位/动作/光线直接改）+ 锁定（锁脸/锁首帧/锁提示词） | 不满意时不用改剧本，只改这一处；重跑不会把已经对的地方改坏 |
| 12 | 多版本对比（标注"这版脸对、动作错"） | 把黑盒变成可管理的生产流程 |

### 3.4 建议的执行顺序（含一个前置动作）

1. **先跑一次真模型 3 镜小样（S6）**——因为首帧模式依赖"把本地图片直接塞给模型"这个前提，如果模型服务不接受，整条主路径要换设计，这比预览功能更紧急；
2. 再做 3.1 止血（不依赖真模型结果）；
3. 再做 3.2 预览与编译器；
4. 最后按需做 3.3。

## 4. 改完之后，你会怎么用（场景演练）

1. 新建项目，粘贴剧本 → 系统切好集数；
2. 点「让 Agent 开始制作」→ 半分钟后得到一整集的生产包（分镜表、资产清单、每个镜头的字段）；
3. 打开「本集待生成清单」→ **每段一行**：这一镜的提示词、会带哪几张参考图、多长、花多少钱，全部看得见；
4. 觉得某镜机位不对 → 展开改一个字段（比如"机位压到地面"）→ 预览立刻更新；
5. 全部看顺眼 → 一键批量生成 → 系统按清单逐段执行，失败自动重试；
6. 出片后不满意 → 三种改法：改字段重生成 / 跟 AI 说"让他先看一眼门再说话" / 锁定已经满意的地方只重跑其余；
7. 得到满意的版本 → 点「采用」→ 系统存档这一版的完整凭证（提示词、参考图、种子），下次想复现随时可查；
8. 整集 20 段都采用 → 合成成片。

**和现在的差别就一句话：每一步花钱之前，你都知道会发生什么；每一笔花完，都留了凭证。**

## 5. 验收清单（可以照着勾）

| # | 验收项 | 通过标准 |
|---|---|---|
| 1 | 预览可用 | 点「预览请求」能看到最终提示词全文 + 参考图 + 模型/时长/分辨率 |
| 2 | 预览 = 实发 | 预览里的提示词与生成后存档的提示词逐字一致 |
| 3 | 预览零花费 | 连续点 10 次预览，Provider 调用次数为 0，费用为 0 |
| 4 | 改词生效 | 在首帧模式下改提示词并生成，出片确实按改后文本 |
| 5 | 体检可信 | 故意漏填一个必填字段，生成前能报错并指出是哪个字段 |
| 6 | 凭证完整 | 任一历史版本可查看：提示词、参考图清单、参数、模型、模板版本 |
| 7 | 批量可预估 | 批量页显示「共 N 段，预计 ¥X」，超出预算需二次确认 |
| 8 | 重启不丢 | 生成中重启服务，任务能恢复或明确标记失败可重试 |
| 9 | 不重复扣费 | 同一段快速连点两次，只产生一个任务 |
| 10 | 脸不跳 | 同一角色的全身图与特写图肉眼可辨为同一人；重出可复现 |

## 6. 附录

### A. 术语表（人话版）

| 术语 | 意思 |
|---|---|
| Agent / AI 导演 | 一个会按技能文档干活的大模型，负责写结构化方案，不直接生成画面 |
| 提示词 | 发给 AI 模型的自然语言指令，决定它画出什么 |
| 结构化字段 | 把"镜头怎么拍"拆成一个个小格子（机位、景别、站位、动作、光线…），而不是一大段文字 |
| 服务端渲染 | 由后端按小格子自动拼出提示词，人不手写（这样能校验、能一致） |
| 首帧 | 一个镜头的第 0 秒画面。先画一张定妆照，再让模型"往后演"，比直接让模型自由发挥稳定得多 |
| 参考图 | 喂给模型的"长相参考"，保证角色不换脸 |
| take | 同一段的一次生成尝试。可以有很多版，挑一版"采用" |
| lint / 体检 | 生成前的自动检查（时长是否够念台词、引用的角色是否存在等） |
| dry-run / 预览 | 只把"要发的请求"算出来给人看，不真的发给模型，不花钱 |
| SSOT / 单一事实来源 | 同一份数据只有一个权威副本和一个翻译出口，避免多处各说各话 |
| 种子 / seed | 控制随机性的数字。同样的种子 + 同样的提示词 = 基本一样的图 |
| 幂等 | 同一个操作执行多次和执行一次结果相同（防止重复扣费） |
| 模板版本 | 提示词模板的编号。存档时记下来，才能知道"当时用的是哪版规则" |
