## 0. 五句结论（面试前只记这 5 句）

1. **岗位本质**：B 端 AI 创作工具的**调优 + 评测 + 流程沉淀**支撑角色，直接贴业务生产一线，带教一对一。
2. **你的匹配度很高**，高到你要主动解释「为什么愿意做实习生」——开发背景 + 自己造过 Agent 流水线 + 真跑过提示词对比实验，这套组合在这个岗位上很稀缺。
3. **面试重心三件事**：你怎么调优（方法论）、你怎么验收（标准）、你怎么沉淀（文档/SOP）。
4. **唯一真缺口**：**内容质量判断力**（JD 第 5 条）。这是开发背景补不上的，也是这两天性价比最高的准备。
5. **实习岗还有一道隐形门**：**到岗时间与时长承诺**，以及「会不会干两个月跑回开发」的稳定性疑虑。

## 3. 三个缺口（按优先级）

### 缺口 A（P0，约 3 小时）｜内容质量判断力

JD 第 5 条，也是你唯一补不上就露怯的地方。但它不难补，且性价比最高。

- **看什么**：20 部爆款短剧的前 3 分钟 + 10 部 AI 漫剧（红果/抖音/快手都行）

## 4. Skill 调优五步法（面试主菜）

**定义问题 → 定指标 → 做基线 → 单变量改动 → 版本对比 → 落地验证**

1. **定义问题**：不要说「效果不好」，要说「哪一类镜头、什么条件下、坏成什么样」。badcase 先分类：串脸 / 崩手 / 动作不跟提示词 / 风格漂移 / 时长不对 / 字幕口型错。
2. **定指标**：一次可用率（抽几次能用）、返工率、平均抽卡次数、单镜耗时、单镜成本、人工评分（1–5）。**必须能落到数字。**
3. **做基线**：固定样本集（同场景、同角色、同提示词、同参数）跑一遍，记下指标。样本不固定就没法比。
4. **单变量改动**：一次只改一个变量（提示词结构 / 时间轴粒度 / 参考图 / 参数 / 模型），否则不知道是谁起的作用。
5. **版本对比表**：同一样本集跑新版，列「指标 / 旧版 / 新版 / 变化 / 结论」，附 badcase 前后截图。
6. **落地验证**：业务方（剪辑/制片）盲评 + 实际采用率。只有「指标改善 + 业务方认可」都成立，才算优化落地。

**面试金句**：
> 「调优不是手感，是把『我觉得好一点』变成『同一个样本集上，可用率从 2/5 提到 3/5、单镜成本从 1.3 降到 0.9 元』。」

**用你的例子走一遍**（这是你的王牌答案）：
- 问题：旧版提示词把散文当指令、标签串、引用后重描、没有站位视线 → 出片废片率高
- 改动：一镜一句 + 时间轴分段 + `@引用` 收敛 + 补站位/视线 → 拆镜 36 段→17 镜
- 指标：失败只损失 4–6 秒的钱（≈1 元/镜）；一次可用率、返工次数
- 结论：**「一镜一句」让失败成本从整段降到单镜**——这就是可复用的方法

## 5. 评测与验收（第二主菜）

| 环节 | 做法 |
|---|---|
| **合格标准** | 把「能用」拆成 Yes/No 条目：角色一致、动作符合提示词、无崩坏、时长对、无口型/字幕错、风格统一。**不用形容词。** |
| **抽检** | 全量自动校验（你的硬校验规则可以照搬）+ 10–20% 人工抽检；badcase 全部进库 |
| **badcase 库** | 分类 + 截图 + 复现参数 + 归因（提示词/参考图/模型/参数）→ 这就是「沉淀调优方法」的实体 |
| **验收报告** | 版本号 / 样本数 / 指标表 / badcase Top3 / 结论 / 是否建议上线 |

**面试话术**：
> 「验收不是『看着还行』，是每个镜头过一遍 Yes/No 清单，badcase 分好类存起来——分类做多了，调优就有方向了。」

## 6. 内容质量评分卡（一页，面试带着）

| 维度 | 看什么 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|---|
| 前 3 秒钩子 | 有没有悬念/冲突/反差 | 平铺直叙 | 有信息钩子 | 立刻想追 |
| 冲突密度 | 几分钟一个反转 | 拖 | 常规 | 密 |
| 节奏 | 单镜时长、信息量 | 拖沓 | 正常 | 快而清楚 |
| 画面一致性 | 串脸、崩手、风格漂移 | 频繁 | 偶发 | 稳定 |
| 声音 | 配音情绪、音效、BGM | 出戏 | 够用 | 加分 |
| 文本 | 台词、字幕、错别字 | 多错 | 少量 | 干净 |
| 结尾钩子 | 追更欲 | 无 | 弱 | 强 |

> 用法：每看一部填一行，面试时能说出「我拆了 30 部，最常见的废片是串脸和动作不跟提示词，这两类都是参考图和提示词的问题，不是模型」。

## 7. 三份文档样例（产品实习的核心证据）

比 PPT 有用。面试说「我平时是这么写东西的」，比说「我会写文档」强十倍。

1. **《Skill 调优记录》1 页**：问题 / badcase 截图 / 假设 / 改动 / 指标对比表 / 结论 / 下一步
2. **《SOP》1 页**：适用场景 / 输入物 / 步骤（谁做、用什么工具、多久）/ 判断标准 / 常见坑 / 验收指标
3. **《工具调研对比表》1 页**：工具 / 环节 / 单次成本 / 速度 / 一致性 / 可控性 / 适合场景 / 结论

**不用新造**：你项目里已有素材（提示词改造对比、三条硬校验、take 标签体系），把它们重排成上面三份即可。
→ 这三份文档 + 评分卡 = 你的「作品集」，比那个 PPT 更能证明「能上手」。

## 8. 业务面问题库（15 题，按 JD 重排）

> 每题 60–90 秒。原则：**先给结论，再给做法，最后给证据。**

**Q1 自我介绍（1 分钟）**
> 软件工程大四，做过两段 Java 后端实习；但我真正的兴趣在「把 AI 能力变成业务结果」。我自己做了一套 AI 短剧生产系统，从剧本到成片跑通，做了提示词调优和效果对比；也因此理解了这条产线的痛点。看到贵司这个岗位是直接进业务一线做 Skill 调优和流程沉淀，我觉得这是我想要的位置。

**Q2 你怎么理解这个岗位？**
> 一句话：产品经理和业务生产之间的「翻译 + 验证」角色。业务说效果不好，我要能定位到是提示词、参考图还是模型；产品改了一版 Skill，我要能用样本集验证它到底有没有变好，并写下来让下一个人能复用。**它的产出不是功能，是可复用的方法和更稳的输出质量。**

**Q3 讲一个你做过的「调优」**
> 用 §4 五步法讲提示词改造的例子，最后落到「一次可用率/单镜成本」的数字。

**Q4 给你一个 Skill，输出质量不稳定，你怎么排查？**
> 先分类 badcase，再按「提示词 → 参考图/资产 → 参数 → 模型能力」四层归因；每一层做单变量对照；找到主因后给最小改动方案，再跑样本集验证。**不先分类就调，等于瞎试。**

**Q5 你怎么定义「这条视频合格」？**
> 用评分卡（§6）：前 3 秒钩子、冲突密度、节奏、画面一致性、声音、文本、结尾钩子。生产端还要加硬指标：时长对、无崩坏、口型对。

**Q6 你怎么写 SOP？**
> 五段结构：适用场景 / 输入物 / 步骤（谁做、什么工具、多久）/ 判断标准 / 常见坑 + 验收指标。关键是**每步都能被新人照着做、被系统校验、被指标衡量**。我系统里把「台词时长 4.5 字/秒 + 2 秒余量」这种经验直接写成硬校验，新人不用背规则。

**Q7 你怎么做工具调研？**
> 按环节列 2–3 个工具，固定四维打分：成本、速度、一致性、可控性；再用 3 条真实样本跑一遍，出对比表 + 结论（什么场景选谁）。**不跑样本的调研报告没有价值。**

**Q8 你平时看短剧吗？怎么判断好坏？**
> 看，而且带着评分卡拆。开发背景让我一开始只盯画面，后来发现真正决定留存的是前 3 秒钩子和反转密度。**我现在能说出一个镜头是「废在参考图」还是「废在提示词」。**

**Q9 你是开发背景，为什么来做产品实习？**
> 两段实习让我看清：AI 写代码又标准又快，纯写实现的价值在下降，价值在「定义问题、验证效果、把方法沉淀下来」。我做那个系统时最有成就感的不是写代码，是发现「一镜一句」能砍掉 60% 的废片成本——那是产品判断带来的。所以我不是转行逃避开发，是找到了自己更擅长的那一段。

**Q10 你以后想做开发还是产品？**
> 产品。开发能力是我的工具，不是我的目标。我想长期做「AI + 内容生产」这一块。

**Q11 你能实习多久？每周几天？什么时候到岗？**
> 每周 4–5 天，可实习到 2027 年毕业，随时可以到岗，有转正意愿。（按你实际情况改，但**必须给确定答案**，不能含糊）

**Q12 你做过最有成就感/最挫败的事？**
> 成就感：把一条产线跑通、真出片。挫败：早期提示词写散文，废片率极高，后来才明白「指令要可执行，不是形容词」。

**Q13 业务方和你意见不一致怎么办？**
> 先用数据对齐事实（同一个样本集各跑一遍），再对齐目标（是要快还是要稳），最后给折中方案 + 小范围验证。**不争论审美，争论指标。**

**Q14 你觉得 AI 在短剧生产里能替代什么？**
> 中间的重人力环节：批量画面、初剪、字幕。不能替代：选题、审美判断、合规判断、跨部门推动。行业里一句话很准：**AI 能把 0 做到 1，1 到 N 还得靠人。**

## 附：行业底稿（精简版，面试当谈资，不用背细节）

**五环节**：剧本创作 → AI 生图 → AI 抽卡 → 剪辑 → 审核/备案。

**八步 SOP 与时间预算**：选题 10min / 剧本+分镜 15–20min / 角色资产锁定 10min / 批量生图 20–30min / 图生视频 15–20min / 配音音效 15min / 剪辑 20–30min / 发布 10min。熟练后单集约 1 小时、一天 3–4 集；行业新人培训 1–3 天上岗。

**关键数字**：2025 年 AI 漫剧市场 189.8 亿元（+276.3%），2030 预计 850 亿；传统漫剧 5000–10000 元/分钟；60 人团队 1–2 天一部 120 分钟；日备案从 200 部涨到 500+；单镜 2–4 秒是漫剧黄金时长。

**成本账（你的实测）**：资产图/首帧 ≈0.3 元，4–6 秒视频 ≈1 元 → ≈1.3 元/镜；一集 12 镜 × 5 抽 ≈64 元；60 集 ≈3800 元；≈51 元/分钟。**最敏感变量是抽卡次数**：多抽一次 = +720 元/部。

**监管三条线（2026）**：AI 内容标识办法 2025-09-01 施行（显式 + 隐式双标识）；AI 微短剧分类分层 2026-07-01 执行；《微短剧发展管理办法》2026-09-01 施行（单集 <20 分钟、三级备案）。平台在清退：红果 2026-04 一周下架 3522 部未备案/未标注 AI 漫剧；《桃花簪》下架 + 停传 15 天。**一句话判断：2026 年从「谁能批量出片」变成「谁能合规地批量出片」。**

**工具地图**：剧本/分镜（DeepSeek、豆包、Kimi）→ 生图（即梦/Seedream、MJ、ComfyUI/SD）→ 图生视频（可灵、即梦/Seedance、Vidu）→ 配音（剪映 TTS、豆包 TTS）→ 剪辑（剪映、FFmpeg）→ 工作流（ComfyUI、Coze、Dify、n8n）。
