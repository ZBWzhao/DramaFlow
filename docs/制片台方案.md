# 制片台改造方案（Studio）

> 一句话：**把「Agent 编排画布」降级为内部结构视图，在上面长一个「制作者用的」三段式制片台——剧本 / 资产 / 制作 / 预览。**
> 保留现有 Agent、Skill、校验、媒体管线、成片管线；不推倒重来。

- 版本：2026-10-17
- 约束：面试复试 2026-10-20（周二）下午；可用工时 ≈ 25–30h
- 演示目标：**60 秒内跑完一条真闭环**（新建 → 剧本 → 分集 → 资产 → 片段 → 生成 → 挑版 → 导出）

---

## 0. 为什么改（一句话证据）

| 证据 | 结论 |
|---|---|
| 两个独立实现（开源 huobao-drama、某商业产品）工作台都是「左栏流水线 + 中间列表 + 右栏检查器」，**都没有节点画布** | 画布不适合承载人的生产管理，只适合展示 Agent 编排 |
| 一集 12 片段 × 60 集 ≈ 700+ 片段 | 人管理 700 条数据的唯一方式是**表格 + 筛选 + 状态列** |
| 现有 9 张画布 89 节点：asset 40 个、**0 个有图**；video_gen 7 个、**0 个有产出**；全 workspace **0 个 mp4/srt/wav** | 系统在「生成之前」武装到牙齿，在「生成之后」手无寸铁 |
| 后端 11,219 行 vs 前端 3,859 行 | 注意力错配：引擎很重，人手很轻 |

## 1. 目标信息架构

```
项目（Project）
├── 剧本（分集列表）        ← 阶段一：粘贴/上传剧本 → 自动分集 → AI 改编
├── 资产                  ← 阶段二：角色(×形象) / 场景 / 道具 / 音色
├── 制作（片段队列）        ← 阶段三：片段列表 → 提示词 → 生成 → 挑版
└── 预览 / 导出            ← 阶段四：集级拼接 → 播放 → 下载 → 标记完成
```

顶栏常驻：`项目名 · 第N集 · 画面比例 9:16 · 模型 xxx · 画质 480P · 完成度 2/12`

左侧栏常驻流水线（5 步，状态由**数据推导**，不靠人点）：
`剧本 → 原始内容 → AI 改编 → 资产 → 片段生成 → 导出`

## 2. 数据模型：旁挂，不动 `core/canvas.py` 的结构

**原则**：所有新信息挂在 `canvas.meta.*` 与节点 `data.*` 上；老画布无这些字段时按「无数据」降级，不报错。

### 2.1 `canvas.meta`

```jsonc
{
  "project": {
    "region": "国内", "genre": "都市情感",
    "style_preset": "写实电影",          // 对应 asset(kind=style) 节点
    "aspect_ratio": "9:16",
    "video_model": "seedance-2.0-mini",
    "quality": "480P"
  },
  "episodes": [
    { "no": 1, "title": "梦中的东京", "script_node_id": "n_xxx",
      "chars": 1187, "status": "in_progress" }
  ],
  "production": { "export_done": false }
}
```

### 2.2 `asset.data`（角色多形象是本次核心差异化）

```jsonc
{
  "kind": "character",           // 已有：character | scene | prop | style
  "name": "宫水三叶",
  "role": "protagonist",         // 新增：protagonist | supporting | extra（主角/配角/龙套）
  "voice_id": "v_xxx",           // 新增：音色绑定（可继承角色级）
  "description": "…",            // 已有
  "consistency_tags": ["…"],     // 已有
  "looks": [                     // ★ 新增：一个角色的 N 套形象
    { "id": "look_1", "name": "系守高中校服",
      "image_path": "assets/generated/xx.png",
      "prompt": "三视图：正脸特写 + 正面/90°侧面/背面…",
      "locked": true,
      "appearances": [{ "ep": 1, "scenes": ["1-2"] }] }
  ],
  "active_look_id": "look_1"
}
```

**兼容策略**：老资产无 `looks` → 用 `outputs.ref.value.path`（若有图）或 `data.image_path` 合成一个隐式 `look_default`。前端一律按 `looks` 渲染。

### 2.3 `storyboard.data`（沿用现有 `shots`，补台词可机读）

现有每个 shot 的 6 字段是 `subject / action / shot_size / camera_move / sound / duration`——
**台词目前被塞在 `sound` 字段里**（如 `"sound": "陈小满：一共两块五。阿岸：姐，扫码。"`）。这是可用的隐式编码，不重构，改为**显式化**：

```jsonc
{ "no": 4, "segment_no": 1, "subject": "陈小满与阿岸", "action": "…",
  "shot_size": "中景", "camera_move": "固定",
  "sound": "扫码枪嗒、纸带落台",       // ← 只留环境音
  "dialogue": [                        // ★ 新增：可机读台词
    { "speaker": "陈小满", "line": "一共两块五。", "kind": "dialogue" },
    { "speaker": "阿岸",   "line": "姐，扫码。",   "kind": "dialogue" }
  ],
  "duration": 4.0 }
```

迁移：读取时若 `dialogue` 缺失，跑一次 `parse_dialogue(sound)`（正则 `^([^：:]{1,10})[：:]\s*(.+)$`）兜底。写入时两者同步（`sound` 只留非台词部分）。

### 2.4 `prompt.data`（片段 = 一个视频生成任务）

```jsonc
{
  "segment_no": 1, "episode_no": 1,
  "duration_s": 17,                  // 新增数值型（现有是字符串 "17s"）
  "references": [                    // ★ 新增：有序引用，取代隐式 {{ref N}}
    { "asset_id": "n_82886d", "look_id": "look_1", "ordinal": 1 },
    { "asset_id": "n_4cc983", "look_id": null,     "ordinal": 2 }
  ],
  "ref_limit": 12,
  "content_path": "assets/n_707ac9/content.md"
}
```

`outputs.prompt.value` / `outputs.text.value` 仍是**纯文本提示词**（人可读可改），其中引用写成 `@角色名` / `@场景名`；
生成前由后端按 `references` 的 `ordinal` 替换为模型可识别的参考图标记。**引用按名字/ID，不按序号排列位置。**

### 2.5 `video_gen.data`（版本用任务表承载）

```jsonc
{ "segment_no": 1, "current_take_id": "media_xxx:n_88ffbe", "tags": ["人脸漂移"] }
```

- **take 历史不新建表**：直接查 `media_job`（`core/media_job_store.py` 已有 `MediaJob`），
  `payload.node_id == 本节点 id && status == "succeeded"` 的记录即历史，按时间倒序。
- 节点 `outputs.video.value.path` = 当前选中版（等价于 huobao 的 `storyboards.video_url` 指针）。
- 好处：零新表；坏处：查询要扫 payload → 加一个 `iter_jobs_by_node(node_id)` 辅助函数 + 内存索引。

1. **新建项目**（9:16 / 480P / Seedance 2.0 Mini）→ 粘贴剧本 → 「自动分集」→ 3 集卡片出现

## 8. 面试要讲的五件事

1. **业务本质**：在不确定性里批量出货。12 片段 × 5 抽 × 60 集 = 3600 次调用，制作者管的是**废片率**与**返工成本**。
2. **三个杠杆**：资产锁定降方差 → 结构化提示词降方差 → take 管理与评级消化剩余方差。（呼应「服务于业务=服务于钱」）
3. **产品架构**：项目 → 集 → 片段 → 资产×形象 → take。
4. **两个独立实现都不约而同不用画布** → 所以我把画布降级为结构视图。
5. **边界与下一步**：双模型审核界限不一致 / 关键帧与转场帧 / Skill 版本化 / 超时 fallback / 成本看板。

**明确不做**（每条配一句为什么）：多集真实生成、团队资产库、音色与 BGM、敏感词过滤、画布重做、成本看板。

## 9. 从 huobao-drama 借的 6 条（已在 `tmp/ref/huobao-drama`）

1. 分镜时长算术：`总时长 = 字数÷500字/分`、`段数 ≈ 总时长÷12s ±20%`、`段时长 ≥ 台词字数÷4.5字/秒 + 2s`
2. 两级粒度：片段 8–15s 含 2–4 子镜，子镜 2–6s，段内不跨场景
3. 视频提示词：信息头 + **每 3 秒一行**，段数 = `ceil(duration/3)`；`@名字` 由代码映射参考图
4. 三种图种分开：角色=三视图、场景=无人物空镜、道具=白底单品；风格词由代码注入
5. 道具「判定三问 + 一集 0–3 个，宁可少提」
6. 成本护栏：默认只跑未生成 / 选择模式才许重出 / 批量前二次确认列清单 / 失败单独重试
