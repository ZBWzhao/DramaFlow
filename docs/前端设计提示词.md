# 前端设计提示词（基于后端真实能力，2026-10-19）

> 用途：把本文档当作「给 AI 前端工程师的施工图 + 提示词」。
> 用法：先投 **§0 主提示词**（一次性建立全局约束），再按模块投 §6 的分模块提示词。
> 原则：**前端只能承诺后端真能兑现的能力**；后端暂时没有的，做成「显式禁用 + 说明」，不做假交互。

---

## 0. 主提示词（可直接复制投喂）

```text
你是一名资深前端工程师 + 产品设计师，负责一个「AI 短剧生成」产品的画布工作台前端。
技术栈固定：Vue 3（<script setup>）+ Vite + 自研画布引擎（web-vue/src/canvas2，绝对不要换成 Vue Flow/React Flow）+ Element Plus（仅用于弹窗/表单/消息）+ 手写 CSS + CSS 变量。不新增依赖，除非我明确批准。

【产品定位】
用户不是"玩节点"的工程师，而是"要做出一集能播的短剧"的创作者。
画布是主工作区：一个镜头 = 一张卡，卡与卡之间用数据流连接（提示词/图片/视频/音频/分镜）。
工作流：项目 → 剧本 → 分镜 → 资产（角色/场景/道具）→ 逐镜生成 → 挑片 → 时间线合成 → 导出。

【必须先读的后端契约（这是硬约束，不许臆造字段）】
1. 画布是一个 JSON 文档，所有写操作都带 revision（版本号）：
   - 缺 revision → 400（错误码 canvas_revision_required，逐步全量收紧中）
   - revision 过期 → 409（错误码 canvas_revision_conflict）；前端收到 409 必须重拉画布、以服务端为准、不要重放写操作。
2. 节点固定 11 种类型：image / video / audio / text / storyboard / asset / prompt / image_gen / video_gen / tts_gen / timeline。
   端口有类型：STRING / IMAGE / VIDEO / AUDIO。连线合法性由服务端判定（剧本归属、端口存在、类型兼容、禁止成环、重复边幂等）。
   前端可以做"类型兼容高亮"作为提示，但**不能把前端校验当成唯一真理**；服务端 400 要把原因显示出来。
3. 生成计划来自 GET /api/canvas/generation-plan：
   { node_id, kind, ready, ready_reason, prompt, prompt_source("prompt_node"|"text_input"|"node"), prompt_overridden, params{duration,ratio,resolution,size}, refs[] }。
   - ready=false 时必须显示 ready_reason（例如"没有可用提示词"），不要只把按钮置灰。
   - 参数有三级来源：节点 data → 分镜镜头时长 → 项目设置（画幅/质量）。生成前必须让用户看到"这次会用 6s / 9:16 / 720p / 720x1280"。
4. 模型选择是**请求级全局的**（provider + model），节点上的 data.model 不参与执行。
   所以：不要做"每张卡一个模型下拉"；做全局模型选择器 + 节点只读展示实际用的模型。
5. 任务状态：queued → running → succeeded / failed / discarded / unknown。
   discarded = 结果被更新一代任务取代（钱花了、不写回，不可重试）；unknown = 远端结果不确定（禁止自动重试，需人工对账）。
   节点状态：draft / ready / generating / done / error。
6. 生成走一次性审批：先 POST /api/canvas/approvals 拿到 approval_id（含参数哈希、10 分钟过期），再 POST /api/canvas/run。
   前端不直接传 approved:true 跳过审批（这是演示环境的临时路径）。正式交互：点生成 → 确认面板（参数/参考/预估成本）→ 审批 → 入队。
7. 任务进度目前没有 WebSocket/SSE（只有 Agent 对话有 SSE），只能轮询 /api/media/jobs/{id}（约 800ms）。
   因此：轮询回来的整张画布数据要做 diff，只局部更新变化的节点；绝对不能每次重拉都重排/重置视口/闪烁。
8. 历史版本：节点 data.takes[]（最近 30 版，含 take_id/path/mime/model/duration_s/rating/note/created_at）+ current_take_id。
   切版 = POST /nodes/{id}/take（带 revision）。UI 要有"当前版"标记与"设为当前版"。
9. 后端没有的能力（不要设计、不要画、不要承诺）：首尾帧控制、音频生成 Provider、ComfyUI 适配、导出画布 JSON、导出成片按钮、边级撤销、实时多人协作。
   这些最多做成"禁用 + tooltip：即将支持"。
10. 服务端已有但前端还没用上的：DELETE /api/canvas/nodes/{id}（级联删边）、POST /api/canvas/edges/delete、POST /api/canvas/arrange（拓扑自动布局）、GET /api/canvas 的 problems（体检问题列表）、POST /api/canvas/export（导出全片提示词 Markdown）。

【设计目标（按优先级）】
1. 视口稳定：生成、轮询、状态变化、拖动，都不许移动相机或重排卡片。只有"换画布/首屏就绪/用户点聚焦"才动。
2. 局部反馈：任何操作 100ms 内必须有视觉反馈；生成状态本地先置 pending，服务端状态回来再校准。
3. 可解释生成：每个"生成"按钮旁边都能回答三个问题——用什么提示词、带哪些参考、什么参数。
4. 显式审批：花钱的动作必须有一次明确确认（参数+参考+成本），确认后凭 approval_id 幂等提交。
5. 渐进披露：默认只显示卡片主体；提示词、参数、历史、详情都在需要时出现（hover/选中/抽屉），画布不拥挤。
6. 键盘优先：专业用户用快捷键完成 80% 操作（删除、复制、多选、聚焦、运行、适配视图）。
7. 电影感暗色画布：画布深色（#08090b 底 + 点阵），卡片深色磨砂，强调色单一（蓝 #6ea8ff），状态色克制，动效 120–240ms。

【视觉规范（用 CSS 变量，不要写死颜色）】
--bg:#08090b; --bg-2:#0b0d10; --panel:#101318; --card:#14171d; --card-2:#171b22;
--line:rgba(255,255,255,.07); --line-2:rgba(255,255,255,.12);
--text:#e9edf4; --text-2:#a7b0bf; --text-3:#6d7787;
--accent:#6ea8ff; --accent-soft:rgba(110,168,255,.16); --warm:#ff8a5c;
圆角：卡片 10–12px，按钮 8px，徽标 999px；间距 4/8/12/16/24；字号 11/12/13/15/20/28。
字体：系统无衬线（-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei"），数字用 tabular-nums。
动效：--dur-fast:120ms / --dur-base:180ms / --dur-slow:300ms；ease-out cubic-bezier(.2,.8,.2,1)；prefers-reduced-motion 时全部关闭。

【信息架构】
- 项目首页：项目卡网格（封面缩略图、标题、集数、片段进度、资产进度、最近更新时间），顶部全局操作（新建项目/导入），无多余说明文字。
- 画布工作台：
  ├ 顶栏：返回、项目名、保存状态/最后同步时间、视图切换（画布/制片台）、全局模型选择、主操作（生成选中）
  ├ 左栏（可收起）：节点/资产列表，搜索（Ctrl/⌘+K 聚焦），按类型分组，点击聚焦对应卡片
  ├ 画布：点阵背景、卡片、按类型着色的贝塞尔连线、选择框、连线拖拽预览、缩放控件（左下）、适配视图、框选、小地图（规划中可后置）
  ├ 卡片：标题行（类型图标/名称/尺寸）+ 16:9 媒体区（图/视频/占位）+ 底部提示词条（选中/悬停展开）+ 端口（左右）+ 状态遮罩
  ├ 浮层：右键菜单（空画布=新建；节点=生成/历史/详情/复制/删除）、节点工具栏（生成这一张/历史/详情）、审批确认弹层、历史抽屉、详情抽屉、Toast
  └ 底部：缩放比例、节点数、视图操作
- 制片台（另一路由）：项目分集、分镜表格/卡片、片段列表（状态/时长/模型/首帧）、片段详情（提示词、参考、历史 take）、合成与成片预览。
- 素材库：资产卡（角色多角度/场景/道具）、按项目分组、上传、预览、引用到画布；显示每个资产的引用次数。
- Agent 侧栏（SSE 流式）：对话、计划/工具调用步骤、产物跳转；不要与画布状态互相阻塞。

【交互规则】
- 缩放：滚轮以光标为锚，范围 15%–220%；<80% 进入 mid LOD（隐藏提示词条/次要信息），<50% 进入 far LOD（只留类型色块+骨架，视频不挂载）。
- 平移：空格拖拽 / 中键拖拽；触控板双指平移，捏合缩放。
- 框选：空白处拖拽；Shift 追加；多选后整组拖动（同组跟手，松手一次提交）。
- 连线：从卡片右侧端口拖到目标卡左侧端口；拖动时只高亮类型兼容的端口，非法释放显示原因 toast；服务端 400 显示原始原因。
- 拖动：本地即时跟手（乐观更新），松手提交；409 时以服务端坐标为准并提示"画布已更新，位置已刷新"。
- 生成：点按钮 → 审批弹层（提示词摘要、参考缩略图、参数、模型、预计费用）→ 确认 → 卡片立即进入"已提交/排队中" → 轮询更新为生成中 → 成功高亮 1.5s / 失败显示"重试" / discarded 显示"结果已过期，未写入" / unknown 显示"结果不确定，请联系维护者"。
- 生成中：禁用该卡生成与删除二次确认提示；不要禁用整块画布；其它卡可继续操作。
- 删除：Delete/Backspace、右键菜单、工具栏；二次确认（有产物时提示"产物文件不删除，历史仍可找回"）；级联删边由服务端完成，前端只重拉。
- 快捷键：Delete 删除、Ctrl/⌘+D 复制（前端 pending 后端接口前先做本地复制+新建调用）、Ctrl/⌘+Z 撤销（规划）、Ctrl/⌘+K 搜索、F 适配视图、Space 平移、Esc 取消选择/关闭浮层。
- 空状态：不写大段文案；用一张"从提示词卡开始"的引导卡 + 一个下拉"新建"入口。
- 错误：一律"人话 + 下一步"。409=画布已更新；400 revision=请刷新；428=需要确认；503=暂时不可用，已退回审批，可重试。

【性能预算（几十个视频节点不卡）】
- 画布 DOM 常驻节点 ≤ 可见节点（视口剔除 pad≈360px），连线只画两端都可见的。
- 视频/图片懒加载：进入视口 + 缩放阈值才挂载媒体；视频只取元数据/首帧，播放时才加载。
- 拖动/缩放走 rAF 合帧，不触发 Vue 深度响应式重算（用 transform + 局部 ref）。
- 轮询数据按节点 diff，只 patch 变化的节点；避免整树重渲染。
- 目标：50 节点、20 视频、1080p 视口下拖动 ≥55fps；首屏可交互 <1.5s。

【可访问性】
- 所有可点元素可 Tab 到达，focus-visible 有 2px 强调色描边；图标按钮必须有 aria-label/title。
- 颜色不是唯一信息载体（状态同时用图标/文字）；对比度 ≥4.5:1（正文）。
- prefers-reduced-motion：关闭 hover 自动播放、位移/缩放动画。

【输出要求】
先给信息架构与页面骨架，再给组件清单（名称、props、事件、状态），再给关键交互的时序，最后给 CSS 变量与视觉稿说明。
不要输出"假功能"（点了没反应、承诺后端没有的字段）；不要用 lorem ipsum；中文文案必须具体、动词开头、≤12 字。
```

## 1. 后端能力 → 前端设计映射（先看这张表再动手）

| 后端能力（真实） | 接口/字段 | 前端应该长成什么样 | 不要做什么 |
|---|---|---|---|
| 11 类节点 + 类型化端口 | `NODE_SPEC`、`/api/canvas` 的 `nodes[].in_ports/out_ports` | 端口用 4 种颜色 + 图标区分 STRING/IMAGE/VIDEO/AUDIO；连线按类型着色 | 不要自造节点类型；不要用"万能连线" |
| 服务端连线校验 | `POST /api/canvas/connect` → 400 原因 | 拖线时前端预高亮兼容口，非法时显示服务端原因 | 不要把前端校验当唯一真理 |
| 生成计划 | `GET /api/canvas/generation-plan`：ready / ready_reason / prompt_source / params / refs | 卡片显示"未就绪原因"、提示词来源徽标、参数摘要、参考缩略图 | 不要只置灰按钮；不要自己猜参数 |
| 参数三级来源 | 节点 `data.duration/ratio/quality/size` → 分镜 → `meta.project` | 生成前展示解析结果，允许在节点上覆盖时长/画幅 | 不要在全局设置里"猜"每张卡 |
| 模型是请求级全局 | `RunCanvasRequest.provider/model`；节点 `data.model` 不参与 | 顶栏全局模型选择器；卡片只读显示"本次用什么模型" | 不要做每卡模型下拉 |
| 一次性审批 | `/api/canvas/approvals` + `/run`（428/409/503） | 生成前确认弹层（参数/参考/预估成本），确认后幂等提交 | 不要前端直接 approved:true |
| 任务 6 态 + 节点 5 态 | `/api/media/jobs/{id}`、`node.status` | 6 态各有明确视觉与文案；discarded/unknown 不可一键重试 | 不要把所有失败都显示成"重试" |
| 仅轮询 | 800ms 轮询整张画布 | 局部 patch + "最后更新"时间；必要时节流 | 不要每轮重排、fit、闪烁 |
| takes 历史（≤30） | `data.takes[]`、`current_take_id` | 历史抽屉（缩略图/模型/时间/时长/评分）、当前标记、设为当前版 | 不要删历史；不要覆盖 |
| 静态资源支持 Range | `/assets/*`（Starlette StaticFiles） | 视频懒加载、seek、首帧、悬停静音预览、大图灯箱 | 不要在 far LOD 挂 `<video>` |
| 时间线 | `timeline_jobs`：clips/trims/audio/tts/subtitle/output | 制片台时间线面板：片段顺序、裁剪、字幕、TTS、输出规格 | 不要做帧级精剪（后端不做） |
| 体检 | `GET /api/canvas` 的 `problems[]` | 体检面板：分组、点击跳转节点、显示修复建议 | 不要在前端重复体检规则 |
| 导出 | `POST /api/canvas/export` 仅 Markdown | 导出按钮 → 下载 Markdown；可展示内容预览 | 不要画"导出成片/JSON"按钮 |
| 删除节点 | `DELETE /api/canvas/nodes/{id}` | 右键/快捷键/工具栏删除，级联删边，二次确认 | 不要自己删边再删节点（事务在服务端） |
| 自动布局 | `POST /api/canvas/arrange` | "整理画布"按钮；按拓扑分层，附预览/可撤销提示 | 不要前端算布局 |
| 素材库 | `media_assets` 注册表 | 素材库页 + 上传 + 引用计数 | 不要承诺"从素材库拖入自动建节点"（后端无此接口） |
| Agent SSE | `/api/events/stream`（仅对话） | 侧栏流式消息/工具步骤 | 不要用它做任务进度 |

## 2. 分模块提示词

### 2.1 画布引擎（canvas2）

```text
在现有 web-vue/src/canvas2 自研引擎上迭代，不要引入 Vue Flow。
要求：
- 相机（x/y/zoom）与节点数据分离；相机用 transform 应用在 stage 上，缩放范围 15%–220%，以光标为锚。
- 视口剔除：只渲染可见节点（pad 360px），只画两端可见的边；连线用 SVG path，按端口类型着色，选中/悬停加粗。
- 三档 LOD：far(<50%) 只留类型色块+骨架、不挂媒体；mid(<80%) 隐藏提示词条/次要徽章；near 全量。
- 交互：空格/中键平移、滚轮缩放、空白框选（Shift 追加）、多选整组拖动、端口拖线（兼容口高亮 + 非法原因）、右键菜单（区分空画布/节点）、Delete 删除。
- 相机稳定：除"换画布/首屏就绪/用户点聚焦"外，任何数据更新（轮询/生成/拖拽）都不许调用 fit。
- 性能：拖动/缩放用 rAF 合帧；卡片位置用 transform，避免整树重算；50 节点 60fps 为目标。
- 给出：组件拆分（CanvasBoard/NodeCard/NodeToolbar/EdgeLayer/SelectionBox/MiniMap 可选）、相机与选中态 store、事件流（pointer 手势状态机）、LOD 判定函数、性能预算。
```

### 2.2 节点卡与生成状态

```text
设计一张"镜头卡"（NodeCard）：
- 结构：标题行（类型图标、名称、尺寸/时长、⋯菜单）→ 媒体区（16:9；图片/视频/占位；视频有三层懒加载 + 悬停静音预览 + 时长徽标 + 播放键）→ 提示词条（选中/悬停展开，Enter 保存）→ 端口（左入右出，类型着色）。
- 五种节点状态：draft 灰、ready 常态、generating 遮罩（转圈+文案+呼吸边）、done 完成 1.5s 高亮、error 红色遮罩+「重试」。
- 任务态叠加：排队中/生成中（可取消规划中）、失败可重试、discarded（结果已过期，不写回）、unknown（结果不确定，联系维护者）。
- 交互：点卡片选中；点播放键选中并打开大图；拖动整卡；右键菜单；生成按钮 busy 时禁用并显示原因。
- 不用 Element Plus 组件，纯手写 + CSS 变量；支持键盘 focus 与 aria-label。
- 给出：props/emits 契约、状态映射表、遮罩/骨架/预览的 CSS 变量与动效参数。
```

### 2.3 审批与任务面板

```text
设计"生成确认"与"任务中心"：
- 生成确认弹层（模态）：本次将生成 N 张；每张显示提示词摘要（可展开）、参考图缩略（带类型徽标）、解析后的参数（时长/画幅/分辨率/尺寸）、模型与预计费用；确认后按 approval_id 提交，按钮进入 loading 且不可重复点；失败按 400/409/428/503 给不同人话提示（503 提示"审批已退回，可重试"）。
- 任务中心（右侧抽屉或顶部胶囊）：按画布分组列出 queued/running/succeeded/failed/discarded/unknown；unknown 单独置顶并给"核对"说明；支持跳转到对应节点；不做"取消"按钮（后端未实现，画了就是假功能）。
- 轮询：只更新任务与对应节点，不刷新整页；显示"最后更新 x 秒前"。
- 给出：弹层信息架构、任务列表字段、轮询状态机、错误文案表。
```

## 3. 常见 AI 前端会犯的错（验收时逐条对照）

1. 每轮轮询都 `fit()` 或重排 → 演示时镜头乱跳（已修过一次，别再引入）。
2. 把 `node.status` 当成本地状态自己猜 → 生成中/失败与后端不一致。
3. 造后端没有的字段：`first_frame`、`last_frame`、`cost`、`progress%`、`edge.label`（无）、`node.model`（不参与执行）。
4. 每张卡一个模型下拉 → 用户以为按卡生效，实际全局生效（误导）。
5. 点生成直接 `approved:true` → 跳过审批，正式环境不该有。
6. discarded/unknown 也显示"重试" → 造成重复扣费或无效重试。
7. 用 `v-if` 频繁销毁挂载视频 → 播放中断/黑屏；应保留播放器、只切 src/暂停。
8. 用 `watch(nodes)` 深监听整棵树 → 大画布卡顿；按节点 id diff。
9. 在 drag 里改响应式大对象 → 掉帧；用局部 ref + transform。
10. 承诺"导出成片/导出 JSON/边级撤销/多人协作" → 后端没有，画了就是假交互。

## 4. 验收清单（给前端 AI 的 Definition of Done）

- [ ] 50 节点画布：拖动、缩放、框选保持 ≥55fps；far 档视频不挂载。
- [ ] 生成：点按钮 100ms 内出现"已提交"；完成高亮；失败出现"重试"；discarded/unknown 文案不同且不误导。
- [ ] 审批：确认弹层能回答"提示词/参考/参数/模型/费用"；重复点被拦；503 后提示可重试。
- [ ] 冲突：409 后重拉画布且不重放写操作；用户看不到英文报错。
- [ ] 视口：除了换画布/首屏/点聚焦，任何操作都不移动相机。
- [ ] 历史：30 版内可翻、可切、当前版有标记；切版后卡片媒体与时长同步。
- [ ] 空态/加载态/错误态：每个页面都有，且不写营销废话。
- [ ] 键盘：Delete、Esc、Ctrl/⌘+K、F、Space 可用；focus 可见。
- [ ] `prefers-reduced-motion` 下无自动播放、无位移动画。
- [ ] 新增依赖为 0（Element Plus 除外）；CSS 只用既有变量；无内联颜色。
