# 系统问题与修复说明（用户版）

> 写给你：一个把项目完全交给 AI、自己没审查过代码的人。
> 目的：用不写代码的说法讲清三件事——**现在系统到底哪里不对、我们正在怎么修、为什么这么修**。
> 对应技术文档：`docs/architecture-fix-plan.md`（完整诊断）、`docs/p0-repro-verify-plan.md`（复现与验证方案）、`tests/p0/`（验证代码）。

---

## 0. 三十秒版本

系统**功能很全、单线程操作基本能用**，但它是在"一个功能一个功能"的节奏里长出来的：每块单独看都对，**没人设计过"两件事同时发生时"怎么办**。

现在正在修的就是这一类问题：**同一份画布上，两个人（或一个人两台设备、或"你"和"后台的 AI 任务"）同时动它的时候，谁的修改会被悄悄盖掉。**

第一批修两件事（**都已完成并验证**）：

1. **谁的编辑算数**（P0-2，已完成）：以前"最后保存的人赢"，现在必须出示"我看到的是第几版"，对不上就拒绝，而不是默默覆盖。
2. **AI 出片的结果不能丢**（P0-1，已完成）：以前模型跑完（钱已经花了）往回写结果时，如果你刚好拖了下节点，系统会把整份结果丢掉，节点永久卡在"生成中"；现在会重新读最新画布、只把自己的结果贴上去、冲突就重试，产物能落地。

后面又成批修了 **P0-8（审批作废但任务没下）、P0-7 / P0-9 / P0-10（生成读不到提示词、出片永远横屏）**，以及合成原子化、Agent 生成统一、任务终态、异常边界、删除节点、拖动回弹、视频卡这一串，见第 2 节与第 3 节。

这几件事听着小，但性质是**不可逆**：钱花了、片子没了、画布还卡住。所以排在最前面。

## 1. 这个系统现在是什么状态

一句话：**像一个装修完但水电没验收的房子。**

| 看起来 | 实际情况 |
|---|---|
| 画布能拖、能缩放、能连线、能生成、有历史版本、有单卡工作台 | 能用，且很多细节做得不错（服务端有端口类型校验、有审批、有任务幂等、有崩溃恢复钩子） |
| 生成会出片 | 能出，但"生成期间你动一下画布"就可能白跑 |
| 多端/自动保存 | 没设计过冲突处理，谁最后保存谁覆盖 |
| 数据持久化 | 有乐观锁字段（版本号 revision），但大部分写入口**不检查**它，等于装了门不锁 |
| 测试 | **此前一个都没有**。改完只能靠人肉点页面，所以"改坏了"经常要等用户发现 |

**问题不是"AI 写得很烂"**，恰恰相反：很多基础设施（审批、任务幂等、租约、崩溃恢复、端口类型）做得比一般外包项目细。真正缺的是**"同时发生两件事"的时序设计 + 能证明对错的自动化测试**。这两样东西 AI 不会主动补，因为需求里没写。

## 2. 前两批修的问题（用生活场景讲）

### 问题 A：画布像"没有版本历史的在线协作文档"

**场景**：你打开画布改了提示词，前端每改一次就自动保存一次。这时后台的 Agent 或另一个窗口也改了一下画布。

**以前发生的事**：两条保存请求赛跑，**后到的直接覆盖先到的**。没有"你改的是旧版本"的提示，没有合并，什么都没了。

**类比**：两个人同时编辑同一份 Word，一个人写"第 1 场：雨夜"，另一个人手里是半小时前的副本，他点了保存——前一个人的内容就没了，而且没人知道自己被覆盖了。

**根因**：系统其实有"版本号"这个设计（每次保存 +1），但接口校验写成了"**版本号为空就放行**"。于是只要客户端漏传（前端漏传、脚本、Agent），就等于没锁。

**现在修成了什么（P0-2，已完成并验证）**：

- 改写画布内容（写提示词、切换历史版本、删除项目）**必须带版本号**；
- 没带 → 直接拒绝（400），提示"请先读取最新版本"；
- 版本过期 → 拒绝（409），前端会立刻重新拉取最新画布，而**不是覆盖**；
- 这三个动作之外，其余接口暂不收紧（见第 4 节"为什么不一次全改"）。

### 问题 B：AI 出片的结果，会因为你拖了一下节点而"蒸发"

**场景**：点"生成"，等 5～30 分钟，模型跑完、钱已经扣了，结果要写回画布。就在写回的瞬间，你拖了一下旁边的提示词卡（或者自动保存刚好触发）。

**以前发生的事**（已验证，不是猜的）：

1. 后台任务读到"画布是第 3 版"；
2. 你的一次操作把画布推到第 4 版；
3. 任务拿着"第 3 版"去保存，被乐观锁挡下；
4. 任务就此**失败退出**：产物写不回去、节点永远停在"生成中"、没有自动重试、没有补偿、界面也不告诉你发生了什么；
5. 模型调用已经发生 → **钱花了，片子没了**。

**类比**：点外卖，骑手到了楼下，你正好挪了一下门口的花盆——系统判定"地址变了"，于是把整份外卖扔了，订单显示"仍在配送中"，钱不退。

**为什么会这样**：写回是"整份画布覆盖"（read → 改 → write）。只要中间有人写，整份就作废。正确做法是"**合并式写回**"：重新读最新画布，只把自己的结果（节点状态、产物、历史版本、当前版本指针）贴上去，再保存；冲突就重试几次。

**现在修成了什么（P0-1，已完成并验证）**：

- 后台任务写回结果前，会**重新读一次最新画布**，只把自己的那部分（节点状态、产物、新历史版本、当前版本指针）贴上去；你刚拖的坐标、刚改的别的卡都保留；
- 保存时如果发现"别人在这中间又改过"，**重读重贴再保存**（最多 5 次），不再整份作废；
- "这个任务是不是已经过期"的判断不变：你重新生成后，旧任务仍然会被丢弃，不会覆盖新结果；
- 测试里的并发用例从红转绿：注入一次拖动后，任务成功、节点"完成"、历史版本 +1、你拖的位置保留。

**修完你能看到的变化**：生成过程中随便拖节点、改别的卡，产物都能落下来；不再出现"生成好了但画布上没有"。

### 问题 C：点"生成"时中途出错 → 审批作废了，但什么都没发生

**场景**：你确认了"这次按这些提示词、这些参考图、这个模型生成"，点了生成。系统内部要做两件事：① 把你这次确认"核销掉"（一次性审批，只用一次）；② 把任务排进队列。

**以前发生的事**（已复现）：

1. 第 ① 步成功——审批状态变成"已使用"；
2. 第 ② 步失败——任务存储那一刻不可用（数据库抖动、进程重启、或者写画布时正好有人拖动）；
3. 结果：**审批没了、任务没下、画布上还挂着一个"当前任务"标记**，指向一个根本不存在的任务；
4. 你刷新再点，系统回"执行参数与审批参数不一致"——只能从头再确认一遍，而且看不出刚才到底发生了什么。

**类比**：在餐厅点了菜、付了钱，服务员把点菜单撕了（核销），结果厨房没收到单——系统记成"已消费"，菜永远不会来。

**为什么会这样**：核销（作废审批）和下单（任务入队）是两步分开的操作，中间没有任何"反悔"机制；而且审批还绑定了"画布是第几版"，中间有人拖一下节点，这份审批就再也用不了。

**现在修成了什么（P0-8，已完成并验证）**：

- 核销和下单合成一个"提交点"：下单失败 → 把"当前任务"标记还原、把审批**退回可用**、返回明确提示"本次没有提交成功，请重试"；
- 审批绑定的是"这次要生成什么"（提示词、参考图、模型、时长、比例），不再绑定"画布是第几版"——所以中间有人拖了节点，刷新后仍能用同一份审批重试；
- 重试、点了两次、网络重发，都会落到**同一个任务**，不重复下单、不重复扣费；
- 为什么不是"先下单、再核销"：那样会出现"任务已经跑起来、画布还没标记"的窗口，后台会把任务当成过期任务丢掉——同样白跑。

---

### 问题 D：把片段拼成"成片"的时候，也会撕单

**场景**：时间线节点点"合成"，系统同样要先核销审批、再排任务；这条路径和"点生成"是两段独立代码。

**以前发生的事**（已复现）：

1. 审批核销之后，如果任务入队失败（存储抖动），审批永久作废、画布上留下"当前合成任务"标记，而任务根本不存在；
2. 更隐蔽的是：合成任务的身份 ID 里绑了"画布是第几版"，失败后你刷新重试，系统会算出一个**新任务**——同一份审批可能被扣两次合成费；
3. 如果激活那一刻正好有人拖了节点，请求直接 409 报错，但审批已经用掉了。

**类比**：和问题 C 同一个毛病，只是发生在"最后剪辑合成"这一步——同样的票被撕了两次、或者同一份订单排了两个厨房。

**现在修成了什么**：合成路径改成和"点生成"完全同一套提交点——失败自动退回审批、回滚"当前任务"标记、返回"请重试"；任务身份只由"审批 + 要合成的内容"决定，刷新重试一定是同一单。

---

### 问题 E：系统把自己的 bug 也汇报成"网络抖动，请重试"

**场景**：你点"生成"，服务端在排队时出了错。以前不管什么错，前台统一显示"暂时不可用，请重试"。

**于是发生了什么**：如果是真 bug（程序写错了一个参数名），你重试一百次都不会好，费用却可能一次次发生；而服务端日志里也看不到出事位置——因为错误被当成"临时故障"吞掉了。

**类比**：医生不管什么病都开"多喝热水"，你反复来、反复挂号，病还在。

**现在修成了什么**：把错误分成两类——"临时故障"（网络、租约、存储连接，过会儿真能好）继续提示"请重试"；"程序自己的错误"（类型错、字段不存在）返回"服务端内部错误，请联系维护者"，并完整记录错误堆栈。两类错误都会把审批退回、把"当前任务"标记还原，不会留下半截状态。

---

### 问题 F：画布只能"加"，不能"删"

**场景**：你想删掉一张试错的卡片，右键菜单里"删除节点"是灰的，提示"服务端暂无删除接口"。

**于是发生了什么**：废稿只能一直留在画布上。卡片越多，拖动/缩放越卡，体检报告全是"这张卡没输入"的噪声，真正要保留的镜头反而找不到。

**类比**：笔记本只能用不能撕，写错一页也留在本子上；本子越厚，翻起来越慢。

**现在修成了什么**：右键菜单可以删节点了，也可以选中卡片按 `Delete` 键删。删除时会把连在它上面的线一起删掉（不会留下"指向空气"的线），删之前弹确认框、会提醒"这一步不可撤销"；如果这张卡正在生成，会额外提醒"本次结果将被丢弃"。删除同样要校验版本号——如果画布刚被别人改过，会让你刷新后重试，不会把别人刚连的线误删。

---

### 问题 G：视频卡被当成图片显示，所以是一张破图

**场景**：视频节点生成好了，画布上却是一个空框/破图；右下角时长永远写 `00:04`；中间那个播放键点下去没有任何反应。

**于是发生了什么**：没人能确认这个镜头到底出没出片——只能去历史记录里翻，或者导出成片才看得到。画布上视频越多，浏览器还要把整段 MP4 当图片请求一遍，白耗流量，也看不出任何东西。

**类比**：相框里放的是录像带。相框只会显示"一张照片"，把录像带塞进去当然显示不出来；而且不管录像多长，相框底下都印着"4 秒"。

**现在修成了什么**：视频卡换成了真正的播放器——先显示真实首帧，时长按这条素材的真实秒数显示（比如 `0:05`）；鼠标悬停时**静音循环预览**，像刷素材卡一样扫一眼就知道镜头对不对；点播放键打开大图（Esc 或点背景关闭，不打断你在画布上的选中状态）。远处/缩得很小的视频卡只显示占位骨架、不加载视频，几十个视频节点的画布也不会卡。

## 3. 修完之后，按顺序还要修什么

写入与提交一致性（P0-2 / P0-1 / P0-8 / 合成路径）、生成正确性（P0-7 / P0-9 / P0-10）、"能删节点"（P0-6）、"拖到哪就是哪"（P0-3）和"视频能看能播"（P0-5）都已修完。剩下按"后果严重程度"排：

| 编号 | 问题（用户视角） | 修完后你能看到 |
|---|---|---|
| P0-4 | 点"生成"会**阻塞十几分钟**，可以重复点导致重复计费，不能取消 | 点一下立刻返回，只下一单，可取消 |

### 本批刚修完的三件事（P0-7 / P0-9 / P0-10）

这三件其实是同一个故事的三段，所以一起修：

1. **卡片里写的提示词，生成时根本没被读**（P0-7）。以前只有"从别的节点连一根线过来"才算有提示词，所以最常见的用法——新建一张视频卡、写上提示词、直接点生成——永远提示"没有输入提示词"。现在的规则是：**连了提示词节点就以连线为准；没连就用卡片自己写的**，两处都有时优先连线，但会标出来"卡里的文字被覆盖了"，不会悄悄丢。
2. **正文存在新位置，老代码只认老位置**（P0-9）。项目改版后，正文写在"卡片数据"和"生成结果"里，但读取代码还在找"磁盘上那个 md 文件"。结果界面里看得到字、生成和导出却拿到空提示词。现在统一成一条读取顺序（文件 → 改写版 → 卡片文字），生成、体检、导出、详情面板全走同一条路。
3. **出片永远是横屏 16:9、5 秒**（P0-10）。画布生成不读项目设置里的竖屏和画质，也不读分镜里每一镜写了多少秒。现在参数按"卡片单独设置 → 分镜镜头时长 → 项目设置 → 默认值"依次取，9:16 的短剧出片就是竖屏，分镜写 6 秒就生成 6 秒。

## 4. 为什么这么改（设计取舍）

**① 先修"不可逆的损失"，再修"体验"**
丢钱、丢产物、卡死 → 最高优先级。拖动回弹、视频破图很烦，但可逆。所以顺序是：写入与提交一致性（P0-2/P0-1/P0-8/合成路径）→ 生成正确性（P0-7/9/10）→ 画布可用性（P0-6/3/5）→ 异步体验（P0-4）。

**② 每次修之前，先写一个"能证明它坏"的测试**
这是这次修复最不一样的地方。以前是"改完点页面看看好像好了"；现在是：

- 先写测试，跑一遍，**亲眼看到它失败**（红灯）——证明问题真实存在，不是我们幻觉；
- 再改代码；
- 同一个测试通过（绿灯）——才算修好；
- 以后谁（包括 AI）改坏了，这条测试立刻变红。

第一条并发用例还配了一个**对照组**（同样的环境，只是没有并发操作，必须成功），用来排除"是不是测试环境本身有问题"。

**③ 小步、可回滚、不动产品功能**
这次不重构、不换架构、不改界面。只给现有系统补三样：**版本号契约**、**合并式写回**、**回归测试网**。每一步都可以单独回滚。

**④ 为什么不一次把所有接口都收紧**
所有写接口其实都该带版本号。但一次性收紧会打断旧版静态画布（`web/canvas.js`）和几个演示脚本。所以先严格化"会改写内容"的三条路径（正文、切版、删项目），其余留到 P1 连同调用点一起改。**风险最小、收益最大**。

**⑤ 用"假模型"验证真实链路**
测试里替换的只是"调用模型"这一步（不联网、不花钱），但**审批 → 排队 → 执行 → 落盘 → 写回画布**全部是真代码。这样既能复现"钱花了"的真实链路，又能稳定重跑 100 次。

## 5. 亮点（这次修复真正值钱的地方）

1. **仓库第一次有了自动化回归网**：`tests/p0/` 是本项目第一个 Python 测试目录。当前 **58 绿 0 红**（P0-2、P0-1、P0-8、P0-7、P0-9、P0-10、合成路径、Agent 生成统一、任务状态语义、异常边界、删除节点、拖动回弹都已转绿，另含防回归：旧任务不能覆盖新结果、重放请求不重复下单、旧画布没有项目设置时行为不变、两个编辑入口交替保存不会读到旧正文、合成失败后同一审批可重试且不重复下单、Agent 触发的生成和按钮触发的生成参数一致、被取代的任务不再冒充成功、服务端 bug 不再伪装成"重试就好"、删节点不会留下悬空线；前端另有 9 条单测锁住拖动落点和视频时长/首帧地址）——"绿"不是终点，是后续每条修复的底线。
2. **问题从"口头描述"变成"可执行的证据"**：并发用例能在固定时机注入一次竞争写入，把"偶尔才发生"的 bug 变成 100% 复现；还能输出当时任务的错误原文（`CanvasConflictError: ... 期望 revision=3，实际=4`）。

## 7. 你怎么验收（不用看代码）

**第 1 步：跑测试，看数字**

```powershell
python -m pytest tests/p0 -q
```

- 现在应该看到：**58 passed / 0 failed**；
- 其中 `test_p0_01_artifact_survives_concurrent_edit` 就是"生成中被拖动"的用例，它通过了就说明产物不会再丢；
- `test_p0_01_stale_task_does_not_overwrite_newer_generation` 是防回归：你重新生成后，旧任务的结果不会盖掉新的一代；
- `test_p0_08_run_atomicity.py` 里三条是"提交失败不丢单"：报错后不留下幽灵任务、审批还能重试、重放不重复下单；
- `test_p0_11_compose_atomicity.py` 里五条是"合成也不丢单"：审批后有人拖节点不影响、入队失败回滚且审批可重试、同一审批重试是同一单；
- `test_p0_07_generation_prompt.py` 里有一条**端到端**用例：新建一张只写提示词的视频卡 → 审批 → 出片，证明"不连线也能生成"真的成立；
- `test_p0_09_text_sources.py` 锁住"正文在哪都能读到 + 两个编辑入口交替保存不会读到旧正文"，`test_p0_10_media_params.py` 锁住"9:16 + 6 秒真的传给模型"；
- 拖拽这条的回归网在前端（`cd web-vue && npm run test:unit`，9 条：拖拽落点 5 条 + 视频时长/首帧地址 4 条）；
- 以后任何一次修复，这个数字都不该从 58 往回掉。

**第 2 步：看几条手工现象**

1. 生成一个视频，**生成过程中去拖动提示词卡**，等结果：画布上应该出现产物、节点变"完成"，而不是"失败"或一直"生成中"；
2. 新建一张视频卡，**只写提示词、不连任何线**，点生成：应该能出片（以前这里会提示"没有输入提示词"）；
3. 项目设置成竖屏（9:16），生成一张图：出来的尺寸应该是竖的（如 720x1280），不再是横屏；
4. **拖一张卡到新位置、松手**：卡片应该停在新位置不弹回；框选几张一起拖，整组应该一起动、松手一次落位；
5. 随便改一下画布内容，看有没有报错（正常不该报错）；
6. 打开两个窗口改同一张画布，后改的那个应该被提示"画布已更新"并自动刷新，而不是悄悄把前一个改动抹掉；
7. **鼠标悬停一张视频卡**：应该看到画面开始静音预览、时长是该素材的真实秒数（不再是 `00:04`）；点播放键打开大图，Esc 或点背景能关掉，关掉后卡片仍是被选中的、不会被误删。

## 8. 术语小词典（看技术文档时对照）

| 词 | 一句话解释 |
|---|---|
| revision（版本号） | 画布的"第几版"。每次保存 +1，用来判断"你手里的是不是最新版" |
| 乐观锁 / CAS | 保存前先核对版本号，对不上就拒绝，而不是加锁把人挡在门外 |
| 409 / 400 | 409=版本过期（请刷新重试）；400=请求缺东西（这里指没带版本号） |
| Worker（后台任务） | 真正去调模型、等结果、把结果写回画布的那个后台进程 |
| 幂等 | 同一个请求重复提交也只生效一次（防止重复扣费） |
| 审批（approval） | 生成前先"冻结"提示词和参数，执行时用冻结值，避免执行中参数被改 |
| takes（历史版本） | 同一个节点每次生成的结果都留一条记录，可随时切回旧版 |
| 回归测试 | 一组"改坏了就会变红"的自动检查，防止修 A 弄坏 B |
