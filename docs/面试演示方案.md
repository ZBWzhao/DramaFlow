# 面试演示方案（2026-10-20 下午）

> 目标：用 **5–7 分钟**展示“从剧本到成片”的完整链路，并让面试官看到工程底牌（并发、任务、版本、测试），而不是只看界面。
> 原则：**演示确定性 > 功能完整度**。能彩排的走彩排，不能可控的（现场建项目、真实模型、重启服务）不上台。

---

## 一、一句话定位（开场 30 秒）

> “这是一个 AI 短剧生产系统：左边是剧本/资产/分镜的创作视图，右边是节点式画布。每个镜头是一次抽卡生成，结果带版本历史；一集的片段接成时间线、经人工审批后合成成片。前端 Vue 3 + Vue Flow 自研画布引擎，后端 FastAPI；生成走可插拔 Provider（Mock / 第三方 API），任务用审批 + 幂等 + 租约保证不重复扣费。”

展示重点排序：**完整链路 → 画布交互 → 任务与数据一致性 → 代码质量**。

## 四、上台前 10 分钟检查

1. 服务只启动**一次**（默认内存任务，重启丢任务）：`python run.py --port 8000`，确认 `/api/health` 200。
2. 确认 `GET /api/media/providers` 的 `active=mock`（现场不扣费、不依赖网络）。
3. 浏览器只开**一个标签页**（避免 revision 互相冲突）；不要刷新页面（内存任务会丢；画布数据本身在磁盘上不会丢）。
4. `ffmpeg -version` 可用（合成/时长探测）。
5. 备份 `workspace/`（尤其 `*.canvas.json`）；出问题可一键还原。今日已额外备份到 `%TEMP%\main.canvas.backup-m1m2.json`。
6. 提前打开一次成片页，确认能播。
7. 准备一段 30 秒录屏（链路总览）作为网络/生成失败的兜底。
8. **画布段先点左侧节点列表的「视频卡·破土升天」**：视口会聚焦到视频卡，右侧工具栏停在卡上方，后续生成/历史都在这张卡上，不用现场找卡。
9. 点卡片正中央是「播放键」：会同时选中该卡并打开大图（这是设计好的大图入口）；如果只想选中卡、不开大图，点卡的上沿/标题行。

## 五、翻车预案（怎么说）

| 现象 | 说法 |
|---|---|
| 生成迟迟不结束 | “这是异步任务。演示环境用的是内存队列、单 Worker；生产会接 Redis/Postgres 和多 worker。我们直接看已有 take 的结果。” |
| Mock 素材是绿底 | “演示模式用 Mock Provider，占位素材、不产生费用；真实模型效果看「钟声」的成片。” |
| 页面刷新后任务没了 | “默认内存存储，重启会丢；部署契约要求 job/invocation/canvas 四个存储一起切 Redis/Postgres。” |
| 被问两个人同时改画布 | “画布有 revision 乐观锁，冲突返回 409 并重拉；生成写回走 CAS 重试，不会覆盖别人的修改。” |
| 被问为什么不用 ComfyUI | “Provider 是 Protocol，Mock 与第三方 API 都已接入；ComfyUI 只是再加一个适配器，接口已经能承载（工作流 JSON + 轮询/WS）。当前没接是因为它需要本地 GPU 环境，不是架构限制。” |
| 被问重复点击会不会扣两次钱 | “run 走一次性审批 + `job_id` 幂等；同一审批重放返回同一任务，不会重复入队。” |

## 六、面试官可能追问（准备 1–2 句）

1. **为什么画布整块存 JSON 而不是节点表？** 一期优先编辑一致性与快照（原子写 + revision CAS）；节点级并发是下一步（位置写独立通道/per-node version）。
2. **任务状态机怎么设计的？** queued → running → succeeded/failed/discarded/unknown；unknown 表示远端结果不确定、禁止自动重试，需人工对账。
3. **怎么保证生成结果不丢？** 审批冻结参数、写回 CAS 重试、旧任务不覆盖新一代（`active_generation_id`）、take 历史保留最近 30 版。
4. **角色一致性怎么做？** 资产卡多角度参考图 + 结构化描述 + 固定 seed（规划中）；目前靠参考图与文本约束。
5. **前后端如何分工？** 前端只管编辑与展示；所有类型/连线/参数校验在服务端只有一份（NODE_SPEC + 端口类型），避免两套规则漂移。
