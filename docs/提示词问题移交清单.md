## 2. 未修，且★会直接吃掉你修复效果的

### ★2.1 首帧模式下，人改提示词是无效的

- **证据**：`GenerateRequest`（`server/studio.py:102` 附近）**没有 `prompt` 字段**。`generate_segment`（1223）里走首帧分支时固定用 `_shot_prompt(shot, ref_names, ...)` 现渲染（1256），完全忽略 `data.prompt` 和 `rendered_by`。
- **后果**：用户在制作页改正文 → `save_prompt` 把 `rendered_by` 标成 `human` → 点生成 → **改的内容根本没进模型**，钱花了，画面没变。这是「白花钱 + 白改」类问题里最容易被误判成「模型不听话」的一条。
- **范围**：只在**已生成首帧**的片段上发生（有 keyframe 就强制走首帧分支）；没有首帧时走 `_materialize_prompt(view["prompt"], refs)`，人改内容是能生效的。所以这个 bug 会表现为「有的片段改得动、有的改不动」。
- **建议**：若你的修复涉及生成入参，优先给 `GenerateRequest` 加 `prompt: str | None`，或用 `view["prompt"]`（已含服务端渲染/人改内容）替代 `_shot_prompt`。

### ★2.2 体检校验的正文，不是实际发出去的正文

- **证据**：`_segment_view`（`server/studio.py:404-409`）用 `_render_segment_text` 渲染 `view.prompt`，`lint_segment` 校验的是这个 `prompt`；而实际发送是 `_shot_prompt`（首帧模式，1256）或 `_materialize_prompt(view["prompt"], refs)`（参考图模式，1273）。三者不是同一份文本。
- **后果**：体检「通过」不代表发出去的对；你修校验相关 bug 时，改的可能是另一条路径的字符串。
- **建议**：把「渲染哪份文本」收敛成一个函数（预览、体检、发送共用同一个返回值），顺带就能实现用户要的「生成前预览」。

### ★2.3 422 硬校验可以被 `body.duration` 绕过

- **证据**：`generate_segment`（`server/studio.py:1233`）`if blocking and not body.duration:` 才 422。前端只要传了 `duration`，哪怕有 error 级 findings 也照发。
- **后果**：你以为「校验拦住了」，其实前端一传时长就绕过去了。这是「正确性 bug 修完仍复现」的常见来源。
- **建议**：把「能不能生成」和「时长从哪来」解耦：`blocking` 一律拦，`duration` 只影响请求参数。

### ★2.4 take 不存提示词/参数快照，结果不可复现

- **证据**：`_run_generation`（`server/studio.py:1166`）写入 take 的字段只有 `take_id/path/mime/provider/mock/model/duration_s/shot_no/mode/created_at`——**没有 prompt、没有 references、没有 seed**。
- **后果**：同一个 take 无法重放；用户说「上一版更好」时既找不回文本也复现不了；后续「生成前预览 / 下架后重发」都缺一份权威输入。
- **建议**：take 里加 `prompt`、`references`、`request`（原始请求 dict）。存储成本可忽略，排查收益极高。

### 2.5 mock 模型会被静默选中 / 静默替换

- **证据**：`_default_image_model`（1129）与 `_default_video_model`（1143）都**优先挑 id 以 `mock` 开头的模型**；`generate_segment`（1244）还会把任何以 `mock` 开头的模型改写成默认模型。所有产物只有 `mock: true` 这个字段能区分，UI 层面无显式提示。
- **后果**：配置错/降级时用户以为在用真模型，实际是占位图；排查时不看 `mock` 字段就会误判「模型质量差」。
- **建议**：mock 只允许在显式指定的 provider 下使用；响应与 UI 都带明显标记。

## 3. 架构级隐患（不急着修，但请别加深）

### 3.1 同一镜数据有六条渲染路径

| 入口 | 函数（行号） | 是否带引用锁 | references |
|---|---|---|---|
| 制片台片段正文 | `_render_segment_text`（1043）→ `_shot_prompt(shot, [])` | 否（`ref_names=[]`） | 不涉及 |
| 视频（首帧模式） | `_shot_prompt(shot, ref_names)`（1256） | **写了 `@名字`** | **`references=[]`** |
| 视频（参考图模式） | `_materialize_prompt(view["prompt"], refs)`（1273） | 是（改写成 `图片N名字`） | 有 |
| 首帧图 | `_keyframe_prompt`（1050） | 是 | 有 |
| 画布分镜表 | `Canvas.render_storyboard`（`core/canvas.py:1081`）→ `_render_shot_block`（1063） | 否 | 不涉及 |
| 资产图 | `_look_prompt`（1602） | 否 | **无 references** |

**风险**：改一处不及其余，就会出现「预览和实发不一样」「首帧对、视频错」。若你的修复落在其中任何一条路径，请顺带确认其余五条是否也符合新规则。

### 3.2 `@名字` 与 references 的语义分裂

- 首帧视频路径正文里写「身份与外观完全按参考素材（@林直人）」，但请求里 `references=[]`（`server/studio.py:1267`）——模型看到的是一段**没有参考图的引用承诺**。
- 参考图模式把 `@名字` 物化成 `图片1林直人`，两种写法混用会让模型理解成「图片」和「人名」两回事。
- **建议**：正文要么不写 `@`，要么保证 `references` 与 `@` 一一对应；这是「换了模型后画面对不上」的高发点。

### 3.3 资产图提示词没有用 `anchors`

- `_PRODUCE_INSTRUCTION`（`server/studio.py:2171`，2199 行附近）要求 Agent 写 `data.anchors`，但 `_look_prompt`（1602）只读 `spec` 里以「外观锚点/构成/场景锚点」开头的行 + `consistency_tags` + 全局风格，**完全没读 `anchors`**。
- **后果**：Agent 认真写的锚点被丢掉，角色一致性只剩 tags 在撑。
- **建议**：`_look_prompt` 优先读 `anchors`（它本来就是为生图设计的短句），`spec` 作为兜底。

### 3.4 `data.references` 是死字段

- `save_prompt` 会写 `target.data["references"]`（717），但全仓库**没有任何地方读它**；引用顺序实际来自画布入边（`_reference_rows` → `canvas.refs_for`）。
- **后果**：如果你正在做「调整参考图顺序」，改这个字段没用，得改边。

### 3.5 「三视图」是静默丢弃的兼容层

- `generate_look`（1646-1650）：正文里出现「三视图」就**静默丢弃** Agent 写的提示词、改用系统模板（画布原文不动）。
- 这是旧规范残留的兜底，等 Agent 不再产出即可删。**别把它当业务规则扩展**。

### 3.6 `rendered_by=human` 是永久锁

- 用户在制作页改过一次正文后，服务端此后**永远不再覆盖**（`server/studio.py:404`、2287）。
- 副作用：Agent 之后重写 `shots` 字段（更好的分镜），用户看到/发出去的仍是旧 human 文本，且没有任何「字段已过期，可重新渲染」的提示。
- **建议**：加 `rendered_by="human-stale"` 或「重新渲染」按钮，而不是二态锁死。

## 4. 契约清单（改代码时不要破坏）

### 4.1 正文唯一入口：`Canvas.read_text`

- `core/canvas.py:670` `read_text` 的回退顺序：**`content.md` 文件 → `outputs.prompt` → `outputs.text` → `outputs.shots` → `data.prompt`**。
- 写入侧契约（你刚在 `save_prompt` 里补的那条）：**只留一个 STRING 槽位**，写 `outputs.prompt` 时 `outputs.pop("text")`；同时写 `data.prompt` 与 `data.rendered_by="human"`。
- 生成、体检、导出、制片台必须共用这一个入口。**任何在 server 里自己实现读取顺序的代码都算违反契约**（`_node_text` 已回归）。
