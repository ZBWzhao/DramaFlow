# 提示词与技能架构（交接文档）

> 写给「新会话接手设计层重构」用。本文件自带全部现状数据与冲突清单，**不需要读会话历史**。
> 配套必读：`docs/提示词改造对比.md`（同一批提示词的新旧原文对照，已交付给用户）。
> 写于 toonflow-py-lab 工艺版 produce 链路跑通之后（项目 `story-钟声-工艺版-a1a46dd6`，17 镜 / 82 秒）。

## 0. 一页结论

1. **规范源重复且互相矛盾**：`skills/workflow` 整棵树 199,998 字节（约 12 万汉字，就是朋友吐槽的「11 万字 skill」同款），其中 `workflow/SKILL.md` 单文件 96,990 字节 / 1442 行会在每次制作时被整篇读入；它内嵌了一整套 `SEEDANCE EPISODE DIRECTOR · PART A`（A0–A12），而新增的 `skills/drama_craft/SKILL.md`（10,122 字节）与它规定**相反**（一镜一段 4-6 秒 vs 每段 ≤15 秒多镜时间轴）。同时 `core/agent.py:464` 还写着「优先读取 workflow，并以它作为**唯一制作主流程**」。
2. **四个 legacy skill 是负资产**：`asset_design` / `drama_script` / `storyboard` / `shot_prompt` 全部标了 `disable-model-invocation: true`（永远不会被自动加载），但描述仍进入系统提示词的技能清单，白占篇幅、制造「我有这个能力」的错觉。其中 `asset_design` 刚被重写过一次，属于白改。
3. **提示词正文不该由模型写**：Agent 现在要手写每一镜几百字正文，质量随模型状态波动、token 贵、且不可校验。渲染器已经在服务端写好了（`_look_prompt` / `_shot_prompt` / `_keyframe_prompt`），但 produce 契约还是「Agent 写长文」。改成「Agent 只交结构化字段、服务端渲染正文」是最大的一次性收益。
4. **校验器与提示词必须同源**：`core/studio_rules.py` 现在靠正则检查「提示词文本里有没有时间分段 / 有没有引用」。正文改成服务端渲染后，这类文本校验全部作废，应改成字段校验。
5. 目标形态：`workflow/SKILL.md` 压到 **< 2KB 路由表** + 4~5 个 2~10KB 分册，工艺只留 `drama_craft` 一份，单次 produce 实际读入规范 **≤ 25KB**（现在 ≥ 107KB）。

### 1.2 加载链路

- 技能清单以 `name + description + location` 形式注入系统提示词，正文靠 `read_skill` 按需读 —— 设计是对的，见 `core/skills.py:93`（`skills_prompt_section`）与 `core/agent.py:449-450` 的 docstring：「技能段只放清单，正文靠 read_skill 按需读 —— 技能数量增长时，每轮请求的上下文不会跟着线性膨胀」。
- 注入点在 `core/agent.py:453-481`：`<tools>` → `<rules>`（20 条，其中 464 是 workflow 唯一主流程）→ 技能清单 → `<guidelines>` → `<cwd>`。
- **问题不在机制，在素材**：机制是渐进披露，但被披露的那一份本身是 97KB 单体文件。渐进披露对「一个大文件」无效——这就是朋友说的「渐进披露加载形同虚设」。
- 更糟的是 `workflow/SKILL.md:66` 自己写：「**Seedance 提示词生成规则已直接嵌入本 workflow**……该内嵌规则是本 workflow 在 Seedance 提示词生成阶段的最高优先级执行规范」；`:92` 又写「从进入 PART A 到最终提示词输出完成，**只执行本文件内嵌 PART A**，不得再读取或套用 references/…」。也就是说：为了保护一致性，把 62KB 的 PART A **整段内联**进了主文件，并用硬隔离阻止模型去读分册。这是用「全量注入」换「一致」，代价正是朋友指出的那三样：token、延迟、以及「一轮 run 要把所有 reference 加进去」。

### 1.3 提示词在 produce 链路里怎么产生（`server/studio.py`）

| 产物 | 生成方式 | 位置 |
|---|---|---|
| 资产素材图提示词 | `_look_prompt(graph, node, kind)` + `_LOOK_RULES`（单角度、身份证工艺） | `server/studio.py:1410` 之后 |
| 首帧图提示词 | `_keyframe_prompt(shot, ref_names, *, full_prompt="")`，8 段式 | `server/studio.py:912` |

## 3. 目标架构

### 3.1 一个切分轴：按**生产阶段**，不按知识类型

现状按「知识类型」切（流程/方法/资产/提示词模板），结果同一件事在多个地方出现（首帧写法在 A12.1、A9.2.0、drama_craft §2 各有版本）。改成按阶段切，一个阶段只有一处：

```
写剧本 ──▶ 拆节拍 ──▶ 排分镜(镜表) ──▶ 资产 ──▶ 首帧 ──▶ 视频段 ──▶ 校验交付
   │          │            │           │        │         │          │
 指南1      指南2        指南2        指南3    指南3     指南3      指南4
                                    └──── 工艺：drama_craft 一份 ────┘
```

## 5. produce 契约改造：Agent 交字段，服务端渲染正文

### 5.1 目标字段（段节点 `data`）

```jsonc
{
  "shots": [{
    "no": 1,
    "duration_s": 4,                      // 3-8，一镜一段
    "shot_size": "近景",                   // 枚举见 _SHOT_SIZE_CODE
    "camera": { "height": "与胸口齐平", "angle": "左前侧 30°", "movement": "固定" },
    "subjects": [{
      "id": "<资产 node id>",
      "screen_pos": "画面左三分之一",
      "gaze": "看向对方喉咙",              // ≥2 主体时必填
      "start_state": "反手把钢筋抵住…",
      "end_state": "两人同时定格，胸口起伏"
    }],
    "props": [{ "id": "<资产 node id>", "state": "螺纹段贴住皮肤" }],
    "action": "反手把 @断裂钢筋 横着抵住 @深棕士兵 的喉咙",
    "focus": "手与喉咙的接触点",
    "light": { "direction": "右后方", "color": "暖橙 2700K", "contrast": "高" },
    "sound": "仅环境音：压抑的粗重呼吸",
    "dialogue": { "text": "", "duration_s": 0 },
    "forbidden": ["不出现国旗国徽文字", "不出现第三个人"]
```

### 5.2 渲染函数对应关系

| 字段 → 正文 | 现有函数 | 要做的事 |
|---|---|---|
| `assets` → 素材图提示词 | `_look_prompt` + `_LOOK_RULES` | 改成纯函数 `render_asset_prompt(node_data)`，不依赖画布图 |
| `shots[0]` → 首帧 8 段式 | `_keyframe_prompt` | 保留结构，输入改为字段 |
| `shots[0]` → 视频段提示词 | `_shot_prompt` | 同上，加「@引用不重描」注入 |
| 景别 | `_shot_size_text` | 不变 |
| 引用展开 | `_replace_ref` / `_materialize_prompt` | 保留兼容 `{{ref N}}` |

标记：服务端渲染的正文写入 `data.prompt`，并置 `data.rendered_by = "server"`；人工改过的置 `data.rendered_by = "human"`（此时不覆盖）。这样既保住可手改，又能校验。

### 5.3 `_PRODUCE_INSTRUCTION` 要删掉的话

现在它要求 Agent「写完整提示词正文」。改成：

- 每条分镜只交 §5.1 的结构化字段，**禁止**在节点里写长正文（正文由服务端 `POST /api/studio/segments/{id}` 视图时渲染）；
- 资产节点只交 `anchors / forbidden / consistency_tags / spec`；
- 删掉「提示词要写成什么样」的所有说明，只留一句「写法见技能 `drama_craft`」。

### 5.4 校验器改造（`core/studio_rules.py`）

废弃（正文不再由模型写，文本正则必然误报）：

- `check_prompt_timeline` 的时间段解析、`_SECOND_RANGE` 的兼容式放宽（`｜` 容错那套可以整段删）
- 「提示词里是否出现引用」的文本检查

新增：

- `check_shots(node)`：`shots` 非空；`duration_s ∈ [3,8]`；`shot_size` 在枚举内；`camera` 三字段齐；`subjects` 非空；≥2 主体时每人 `gaze` + `screen_pos` 必填；`action` 里的 `@名字` 全部在 `props/subjects` 里（引用闭包）；`forbidden` 非空。
- `check_asset(node)`：`kind/name/anchors/consistency_tags/spec` 非空；`spec` 不得含「三视图」。
- 保留 `check_references` 的「引用是否都用上」语义，但改为对照入边集合而非文本。

## 8. 不做的事 / 风险

**不做**：

- 不做 RAG。朋友说的 RAG 针对的是「企业知识库级」内容；本系统的「大知识」是**资产档案和历史剧情**，它们已在画布节点里，按边取 refs 就是天然的切片。规范类内容用分册 + 路由即可，检索只会增加不确定性。
- 不给 skill 继续加 references 而不减总量。分册的目的是「一次只读 1–2 册」，不是「把 200KB 变成 10 个 20KB 文件」。
- 不把 `references/methods/*`（63KB）搬进产线。它是「剧本/设计阶段」的知识，保留现开关：`workflow/SKILL.md` 里只在剧本未定稿时指过去。

**风险**：

1. **拆分丢规则**。缓解：迁移时按 §4 逐条登记去向，拆完用 `diff` 对照原文件行数，确保每个 A 小节都有归处。
2. **2.5 时间轴能力被误删**。缓解：A9.2 不进技能，单独存 `docs/seedance-25-timeline.md` 备查，并在 `drama_craft` §3.3 写一句「本系统当前按一镜一段，2.5 的时间轴写法未启用」。
3. **删 legacy 影响历史画布**。不影响：历史节点正文已存在 `canvas.json` 里，删 skill 只是不再引导模型读；但要在 `docs/` 记一笔「旧画布不保证符合新规范」。
4. **KV cache 又被破坏**。`core/agent.py:453-481` 的拼装顺序是「稳定前缀（tools/rules/技能清单）→ 可变（cwd）」，这是对的；改 rules 时只改文本、不要改顺序，改完前后各测一次首 token 延迟。
