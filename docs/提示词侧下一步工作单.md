### T1｜★2.1 首帧模式忽略人改正文（P0，0.5–1 天）

**目标**：用户改了正文 → 点生成 → 发出去的 `request.prompt` 必须包含人改内容，**包括已有首帧的片段**。

**现状（已核实）**
- `GenerateRequest`（`server/studio.py:102-110`）没有 `prompt` 字段。
- `generate_segment`（`server/studio.py:1225`）里首帧分支（`use_keyframe=True`，约 1255-1272）固定用 `_shot_prompt(shot, ref_names, ...)` 现渲染，**完全忽略 `data.prompt` 与 `rendered_by`**。
- 参考图分支用的是 `view["prompt"]`（`_materialize_prompt`，约 1274），所以「有的片段改得动、有的改不动」。
- `_segment_view` 的 `prompt` 已经是人改感知的：`prompt = _node_text(canvas, node)`（`server/studio.py:360`），当 `rendered_by=="human"` 时不会被 `_render_segment_text` 覆盖（`server/studio.py:404-407`）。

**修法（推荐 A，兼容性最好）**
- A：给 `GenerateRequest` 加 `prompt: str | None = None`；首帧分支改为：
  `prompt_text = body.prompt or (str(node.data.get("prompt") or "").strip() if rendered_by == "human" else _shot_prompt(...))`。
  更简单的等价写法：`prompt_text = body.prompt or (view["prompt"] if rendered_by_human else _shot_prompt(...))`。
- B（更彻底）：首帧分支直接用 `view["prompt"]`，`_shot_prompt` 只作为「服务端渲染源」被 `_render_segment_text` 调用。
- 选 A 还是 B 取决于你要不要保留「首帧模式用镜头级短提示词」的旧行为；不论选哪个，**必须新增一条测试覆盖首帧模式**。

**注意（别引入新问题）**
- 首帧模式 `references=[]`，正文里的 `@名字` 会变成「没有参考图的引用承诺」（移交清单 §3.2）。若本次保留 `@`，请顺手把 §3.2 一起处理（至少不要在新路径里新增 `@` 承诺）。
- 改完检查 `demo/s4_render_check.py` 的 `人改正文未被覆盖: True` 仍成立。

**验收**
- 新增 `tests/prompt/test_t1_first_frame_honors_human_prompt.py`（可复用 `tests/p0/conftest.py` 的临时画布夹具；不要改 `tests/p0/` 里的文件）：
  1. 建 storyboard → prompt → video_gen 的最小画布，给 video_gen 设 `data.keyframe={path: <占位文件>}`；
  2. 调 `save_prompt` 写人改正文（断言 `rendered_by=="human"`）；
  3. `monkeypatch` 掉实际媒体调用（不要花钱），调用 `generate_segment(use_keyframe=True)`；
  4. 断言：请求里的 prompt 含人改正文；旧代码该断言失败。
- 门禁：`pytest tests/p0 -q` 35 passed + 6 个脚本 exit 0 + 新测试绿。

### T2｜★2.3 422 硬校验可被 `body.duration` 绕过（P0，0.2 天）

**现状（已核实）**：`server/studio.py:1233-1238`
```python
blocking = [item for item in view["lint"]["findings"] if item["severity"] == "error"]
if blocking and not body.duration:   # ← 传了 duration 就绕过
    raise HTTPException(422, ...)
```

**修法**：`if blocking: raise 422`（与 duration 解耦）；`body.duration` 只影响 `request.duration` 参数。

**验收**
- 测试：构造带 error finding 的片段 + `body.duration=5` → 期望 422（旧代码 200/202）。
- 测试：修好 finding 后 `duration=7` → 请求 `duration` 为 7。
- 检查调用方是否依赖旧行为：`grep -R "duration" server/studio.py web-vue/src`、`demo/*`，前端若靠传 duration 硬闯，改为先修锁或明确报错提示。

### T3｜★2.2 体检 / 预览 / 实发用同一份正文（P1，0.5–1 天）

**现状**：`_segment_view.prompt`（体检用）= `_node_text`/`_render_segment_text`；实发 = `_shot_prompt`（首帧）或 `_materialize_prompt(view["prompt"], refs)`（参考图）。三份文本。

**目标**：一个函数产出「要发出去的提示词」，预览、体检、发送、导出共用：
```
render_segment_prompt(canvas, node, shot_no, refs) -> {"prompt": str, "source": "prompt_node|node|server_render", "refs": [...]}
```
- 必须复用 `Canvas.resolve_prompt` / `Canvas.read_text`（单一入口）。
- 让 `_segment_view` 的 `prompt`、`lint_segment` 的输入、`generate_segment` 的 `request.prompt` 都来自它。
- 顺带实现「生成前可预览」的最小接口（可只在前端详情里显示，不必新路由）。

**验收**：新增测试断言「同一片段同一 shot_no，预览 prompt == 实发 prompt」；体检结论基于同一文本。

### T4｜★2.4 take 增加输入快照（P1，0.5 天，有前置锁）

**前置锁（未解锁前不要做）**：画布侧会先抽 `append_take(node, take)` helper，让「制片台 `_run_generation`」与「画布 Worker 成功回写」共用一份 take 写入逻辑。**解锁标志**：`server/app.py` 或 `core/canvas.py` 中出现 `append_take` 符号，且 `docs/提示词问题移交清单.md` §8 标注 T4 解锁。若你开工时还没出现，先做 T3/T5，不要自行加字段（否则两条路径会各加一份，产生第三个双轨）。

**修法（解锁后）**
- 在 helper 里统一加字段：`prompt`（实发文本）、`references`（图片路径列表）、`request`（原始请求 dict，含 provider/model/size/duration/ratio/resolution/shot_no/mode）、可选 `seed`。
- 两条路径都走 helper；画布侧仍保留「只留 30 版」截断。
- 旧 take 无这些键：读取方必须 `take.get("prompt")` 容错。

**验收**：制片台生成一次 + 画布生成一次，断言两边 take 都含 `prompt/references/request`；`tests/p0/test_p0_01_generation_writeback.py` 仍绿；`pytest tests/p0` 35 passed。

### T5｜§2.5 mock 不再被静默选中/替换（P1，0.5 天）

**现状**：`_default_image_model`（1129）/`_default_video_model`（1143）优先挑 `mock*`；`generate_segment`（1244-1245）把任何 `mock*` 静默改写成默认模型；UI 无提示。

**修法**
- 默认模型选择**不**优先 mock；mock 只在 `provider=="mock"` 或用户显式指定 `model=mock-*` 时使用。
- 请求的 model 与 provider 不匹配（如非 mock provider 传 mock 模型）→ 返回明确 400，不静默替换。
- 响应与前端状态把 `mock` 标记显出来（take 已有 `mock` 字段，历史抽屉目前可能没显示）。

**验收**：单元测试断言「无参数时 `_default_*` 不返回 mock」；「provider=tfrouter + model=mock-x」→ 400；画布侧 smoke 会顺手断言 `mock` 标记（画布会话负责，不冲突）。

### T6｜§3.6 `rendered_by=human` 从「永久锁」改为「可判过期」（P2，0.5 天，需协调）

**现状**：用户改过一次正文后，服务端永远不再覆盖（`server/studio.py:404`、`_sync_rendered_prompts` 约 2287），Agent 更新 `shots` 后用户看到的仍是旧文本，且无提示。

**修法（建议）**：保存人改文本时记录 `data.render_source_hash = sha256(structured_fields)`；`_segment_view` 对比当前 hash，不一致返回 `stale=True` + 「按新分镜重新渲染」操作（用户点击才覆盖）。**不要自动覆盖人改内容。**

**协调**：`save_prompt` 画布会话刚改过（槽位清理）。开工前在认领表登记，基于当前工作树改，别用旧备份。
