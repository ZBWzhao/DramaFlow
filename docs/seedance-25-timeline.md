# Seedance 2.5 时间块提示词写法（备查 · 当前系统未启用）

> **当前系统按「一镜一段、单镜 3–8 秒」出片，不启用本文件描述的时间块方案。**
> 本文件只在两种情况下读：① 需要为未来恢复 2.5 多时间块能力做准备；② 排查历史 2.5 产物。
> 现役写法见 `skills/drama_craft/SKILL.md` 与 `skills/workflow/references/`。

## 1. 格式硬门

目标模型为 Seedance 2.5 时，最终交付只能是下列字段结构。除段头信息外，允许的顶层字段仅为：
`Objective`、`Reference binding`（仅存在真实参考资产时出现）、`Immutable locks`、`Target duration`、`Timeline`、`Visual direction`、`Audio direction`、`Preserve`、`Avoid`。

**禁止把任何中间规划稿、其他模型模板或非本结构的外壳直接作为 2.5 最终交付。** 除段头与白名单字段外，正文不得出现其他顶层字段、编号式分镜章节或额外分析块。

`Timeline` 必须用 `【0:00-0:XX】` 时间块 + 连续自然语言。镜头变化只能嵌在对应时间块的自然语言里，不得另立镜头编号体系作为主结构。

内部草稿采用其他结构时，只当**源材料**：先按剧情保真锁与节拍账本解析，再在交付前重排进白名单字段。最终正文出现白名单之外的顶层结构即判定格式失败，不得交付，本轮直接改写。

## 2. 模板

```text
═══════════════════════════════════════════
G0N｜Batch X / 段 N ｜目标模型：Seedance 2.5 ｜本段时长：Xs ｜全局时间：MM:SS–MM:SS
═══════════════════════════════════════════

Objective:
用 1–2 句说明：本段在整集中的位置、时长/画幅/总体质感，以及这一段的戏剧目标。不要复述完整 Timeline。

Reference binding:
- 自动读取本段剧情、镜头、动作与画面内容，提取本段实际涉及且需要调用的参考资产（角色图、场景图、商品图、道具图、站位图等）。
- 对提取出的资产做简洁标识，说明对象或用途即可：「男主角色参考」「客栈场景参考」「产品包装参考」「红绳道具参考」。
- 凡用户已提供且本段实际需要的真实参考图片或资产句柄，必须逐一列出并原样保留节点 ID / 资产句柄，不改写、不缩写、不重新编号。
- 同一资产上一段已用、本段仍涉及，必须在本段重新列出；禁止「同上」「沿用上一段参考」。
- 只提取本段实际涉及的资产，不把未出现的资产机械加入。
- 无需逐张解释「控制什么/不控制什么」，只做简洁明确的身份标识。
- 本段没有真实参考时整节省略。
- 严禁根据剧情编造 {{node/image-...}}、资产编号、引用标签或不存在的素材。

Immutable locks:
- 只写直接影响生成稳定性的不可变条件：角色身份与服装、关键世界位置与左右关系、连续场景的光线逻辑、关键道具状态、商品结构、对白原文与口型、必要的画外锁定。
- 不把整段剧情重抄一遍。
- 连续场景跨段时，把上一段结束状态改写成本段的绝对初始状态，不写「延续上一段」。

Target duration: X seconds

Timeline:
【0:00-0:XX】一段连续中文自然描述这一时间块真正看见的画面：必要的场景/站位、当前出镜状态、景别或切镜、动作先后、关键表演反应、同期对白、关键道具变化与必要物理细节。像成片描述一样写，不拆成「摄影机/动作/表演/台词/物理」等子标题。

【0:XX-0:XX】继续用一段连续自然语言描述后续画面。

Visual direction:
用一个紧凑自然段概括整体摄影质感、光线、色温、景深、人物与商品的视觉关系及必要物理质感。只写真正影响这一段的视觉要求。

Audio direction:
- 物理拟音 / 环境音：……
- 对白人声：……
- 用户明确要求配乐时才写配乐；未要求时默认「无背景音乐，仅保留真实同期声与环境音」。

Preserve:
一行或一个短自然段，列出必须保留的角色造型、场景锚点、商品结构、关键道具状态、空间关系或动作逻辑。

Avoid:
一行或一个短自然段，列出最容易出错且与本段直接相关的问题；不堆泛化负面词。
```

## 3. Timeline 写法（强制）

必须「时间块 + 连续自然语言画面描述」。示意：

```text
Timeline:

【0:00-0:06】
在源剧情已经明确的场景中，角色A执行 E01 的原始动作。镜头按需要从建立镜头切到角色A中景；若角色B在该节拍按原文保持画外，就明确写「角色B保持画外」。只补充能直接看见的姿态、接触、物理反馈，不新增拿取、开盖、走位等源剧情没有的事件。

【0:06-0:12】
承接 E02–E03。角色A按原文说出台词，角色B按原文做出既有反应。可以把已有反应写成具体可见动作，但不能把「反应」扩写成新的剧情行为。必要时切近景或局部特写，剧情事件顺序不变。

【0:12-0:18】
承接 E04。若本时间块首帧源剧情已经规定某道具在角色手中，就直接从该状态开始，不追溯、不补写道具如何被拿到手里。镜头只负责呈现，不负责补前史。
```

执行要求：
- 每个时间块通常 1 个自然段，信息够用即可；块数按剧情自然决定，不固定为 3 或 4 块。
- 可直接写「切男主近景 / 切手部特写 / 回双人中景」，不必额外建立镜头编号。
- 只写对当前时间块有实际影响的站位、左右、画外状态与连续性，不机械重复 `Immutable locks`。
- 角色不应出现时简短写「女主保持画外，不自动补入镜头」。
- 台词直接嵌在对应动作位置，不在 Timeline 后重复。
- 物理细节只写与当前动作直接相关的（液体晃动、衣料接触、道具表面湿润、重量、碰撞反馈）。
- 每个时间块优先保持一个清晰动作链，不为信息完整把每秒塞满。
- 描述重点是「这一刻成片实际看见什么」，不是重新解释规则。
- 每个会改变人物/道具/位置/数量/关系/信息的动作，都必须来自源节拍 `E##`；不为「更顺/更完整」补拿取、开合、抽取、递交、起身、走位、回头、使用次数、道具消耗。
- 源剧情从既定状态直接开始时就直接写该状态，不追问它之前怎么发生。
- 原文用「父母/家长/成人/某人」等泛称时 Timeline 保持同样泛称，除非用户最新指令已指定具体人物。

## 4. Reference binding 硬规则

- 只引用用户真实提供的参考节点、图片标签或资产句柄，**原样保留完整节点/句柄**；禁止改名、缩写、重新编号或编造不存在的引用。
- 每个真实参考单独列一行，采用「**真实节点/句柄：简洁资产标识**」写法。
- 不要求逐张展开「控制什么/不控制什么」；但内部仍须遵守用户明确用途：角色图不得越权改变站位，站位图不得覆盖人物身份，场景图不得额外带入人物或道具。
- 用户明确说「仅位置参考/仅服装参考/仅产品参考」时，标识必须保留用途限定。
- **每段自包含**：上一段用过的参考本段仍需要时必须再次列出，禁止「同上」「沿用上一段参考」。
- 只列本段实际需要的资产，不把全集参考库塞进每一段。
- 没有真实参考时省略整个 `Reference binding`；禁止伪造 `{{Ref}}`、`{{node/image-...}}`、资产编号或不存在的资产名。

## 5. Immutable locks

只保留不可漂移的信息，例如：男主白衣、女主红衣；女主在桌南侧/画面左，男主在桌北侧/画面右；商品蓝色翻盖结构；某角色在某时间块保持画外；原文对白不改词不吞字；连续场景灯光方向与道具状态不重置。

不要把会在 Timeline 内变化的动作写成 lock。

## 6. Audio direction

用户明确要求 BGM/配乐 → 按用户要求写；未要求 → 默认无 BGM、无情绪提示音，只保留真实环境音、物理拟音与同期对白。不因示例里出现过配乐就把配乐变成默认行为。

## 7. Preserve / Avoid

两者都服务当前段执行，保持短：`Preserve` 写真正不能漂移的造型、空间、商品、道具、动作逻辑；`Avoid` 写当前段最可能发生的生成错误；不写几十个泛化标签。

## 8. 与现役方案的关系

| 维度 | 2.5 时间块方案（本文件） | 现役一镜一段方案 |
|---|---|---|
| 生成单元 | 一段含多个 `【时间块】` | 一镜一段，3–8 秒 |
| 段内时间轴 | 必需 | **禁止** |
| 段间衔接 | 时间块自然语言延续 | 独立生成，靠 5 块自包含信息 + 镜间差异规则 |
| 正文作者 | 模型按字段模板写 | 服务端按结构化字段渲染 |

恢复 2.5 方案前必须先验证：视频模型真的会按时间块切镜，而不是把多段糊成一条。当前实测结论是后者。
